# 명령어 농장 컨셉 분석

작성일: 2026-11-26 · 기준 문서: `아이디어 정리.md`

사용자가 기획한 **방향 C(명령어로 진행하는 농사 타이쿤) "Lupin Farm"**을 분석하고, 사용자 답변(2026-11-26)을 반영해 정리한 문서다. 사용자가 이 방향으로 진행하기로 했다. 터미널 도트 렌더링 방식은 `기술 스택 조사.md` 4~5절, 농사 메커니즘 일반은 `생활 시뮬·RPG 메커니즘 조사.md` 1절을 따른다.

## 1. 컨셉

Claude Code처럼 생긴 터미널 화면에서 **영어 슬래시 명령어**를 입력해 농장을 운영하는 **농사 전용 타이쿤**이다. 심고 팔아 번 돈으로 땅, 농기구, 작물에 투자하고, 최종적으로는 **농장이 알아서 돌아가도록 자동화를 구축**한다. 엔딩 없이 무한히 성장하며, **지난 판의 기록을 깨는 것**이 장기 목표다.

| 항목 | 내용 |
| --- | --- |
| 이름 | Lupin Farm |
| 장르 | 방치형 + 자동화 농장 타이쿤 |
| 조작 | 영어 슬래시 명령어, 선택지 입력, 단축키, 마우스(페이지 버튼) |
| 콘텐츠 | 농사만 한다. 주민, 전투, 캐릭터 이동은 없다 |
| 시간 | 실제 시간 기반 배속 (예: 실제 1분 = 게임 1시간) |
| 화면 | 위: 도트 농장 영역 / 아래: 명령어와 게임 로그 |
| 문구 언어 | 영어 기본, 설정으로 한국어 |
| 끝 | 없음. 무한 성장 + 기록·랭킹 + 프레스티지 |

## 3. 화면

### 3.1 배치

```text
 ✻ Lupin Farm                                          Spring 3 · 14:00 · 1,240G
┌─ field 1/3 ──────────────────────────────────────────────────────────────────┐
│ ◀  [pixel farm]                            field 1     30/30 plots         ▶ │
│    10 x 3 plots (A1 ... C10)               sprinkler   x2                    │
│    1 plot = 8x8 px = 8 cols x 4 rows       harvester   Lv1                   │
│    half-block pixels, 80 cols x 12 rows    auto        #1 #2 on              │
│                                            next        turnip 0:42           │
└───────────────────────────────────────────────────────────── ● ○ ○ ──────────┘
> /harvest ready
● Harvest(field 1)
  ⎿  turnip x12 → storage 24/40

● Auto#2(sell turnip)
  ⎿  +420G (32G ▲2)

✻ Growing… potato A5:A8 ready in 1h 12m
╭──────────────────────────────────────────────────────────────────────────────╮
│ > /auto add when f1 ready do harvest                                         │
╰──────────────────────────────────────────────────────────────────────────────╯
  ? for shortcuts · PgUp/PgDn field · Tab complete
```

(농장 영역은 줄여서 그렸다. 실제로는 도트 12줄이다.)

| 영역 | 높이 (120×30 창 기준) | 내용 |
| --- | --- | --- |
| 헤더 | 1줄 | 게임 이름, 계절·날짜·시각, 골드 |
| 농장 영역 | 14줄 (테두리 포함) | 도트 농장 1구역 + 오른쪽 구역 정보 + 양옆 `◀` `▶` + 아래 테두리에 페이지 표시 |
| 로그 영역 | 나머지 (약 11줄) | 내가 친 명령어, 실행 결과, 자동화 실행 기록, 진행 중 작업 스피너 |
| 입력창 | 3줄 | 둥근 테두리 입력창 |
| 안내 | 1줄 | 단축키 안내. `/`를 치면 자동완성 목록이 펼쳐진다 |

### 3.2 농장 영역 크기

원래 기획은 위 1/3이지만, 도트로 그리면 1/3(기본 창에서 10줄)로는 부족하다. 그래서 **농장 영역은 비율이 아니라 고정 높이**로 두고, 남는 줄은 모두 로그 영역에 준다. 창이 커질수록 로그가 길어진다.

반쪽 블록 도트는 글자 1칸 = 가로 1픽셀 × 세로 2픽셀이다.

| 밭 한 칸 | 글자 수 | 구역 하나 (밭 배치) | 농장 영역 높이 | 120×30 창에서 비율 |
| --- | --- | --- | --- | --- |
| **8×8 픽셀 (추천)** | 8칸 × 4줄 | 10칸 × 3줄 = 80칸 × 12줄 | 14줄 | 약 1/2 (최대화하면 약 1/4) |
| 6×6 픽셀 | 6칸 × 3줄 | 12칸 × 3줄 = 72칸 × 9줄 | 11줄 | 약 1/3 |

- 8×8을 추천한다. 사용자가 영역을 늘려도 된다고 했고, 작물의 자라는 단계를 구분해 그리기에 6×6은 너무 작다.
- 가로 120칸 = 테두리와 `◀` `▶`(약 8칸) + 구역 도트(80칸) + 구역 정보(약 30칸).
- 최소 창 크기는 120×30이다. 창이 넓으면(약 200칸 이상) 구역 2개를 나란히 보여 준다.

### 3.3 도트 에셋

| 종류 | 내용 |
| --- | --- |
| 땅 | 마른 흙, 젖은 흙, 아직 안 산 땅(풀·울타리). 계절마다 풀과 흙 색이 바뀐다 |
| 작물 | 작물마다 4단계: 씨앗 → 새싹 → 자라는 중 → 다 자람 |
| 장비 | 스프링클러 Lv1~3 (밭 한 칸을 차지한다) |
| 시간 | 밤(22~06시)에는 농장 영역 전체를 어둡게 칠한다 |
| 프레스티지 | 농장 전체에 루피너스가 피는 장면 (7.4) |

도트는 이미지 파일 없이 코드 안의 문자 그리드 + 팔레트로 만든다. 예: 다 자란 순무

```text
"..g..g.."    . 흙
"..gggg.."    g 잎
"...gg..."    w 순무 흰 부분
"..wwww.."    p 순무 보라 부분
".wwwwww."
".ppwwpp."
"..pppp.."
"........"
```

### 3.4 Claude Code 디자인에서 가져올 요소

배치와 분위기만 가져온다. 로고나 이름은 쓰지 않는다.

| Claude Code 요소 | 게임에서의 쓰임 |
| --- | --- |
| 시작 환영 상자 | 시작할 때 부재 중 요약 (꺼져 있던 동안 수확·판매 결과) |
| 둥근 테두리 입력창 `╭ > ╮` | 명령어 입력 |
| `>` 내 입력 줄 | 내가 친 명령어 기록 |
| `●` 결과 + `⎿` 세부 줄 | 명령 실행 결과. `● Harvest(field 1)`처럼 도구 실행 기록 형태 |
| `✻ Thinking…` 스피너 | `✻ Growing…` 진행 중인 작업 표시 |
| `/` 입력 시 자동완성 목록 | 명령어, 작물, 아이템 이름 자동완성 |
| 번호 선택지 질문 | 비싼 구매, 프레스티지 확인 등. "1. Yes 2. No"를 번호나 방향키로 고른다 |
| 어두운 배경, 주황 강조색, 회색 보조 글씨 | 전체 색 구성 |

### 3.5 문구 언어

| 항목 | 내용 |
| --- | --- |
| 기본 | 영어 |
| 바꾸기 | `/config lang ko`, `/config lang en`. 바로 적용되고 저장된다 |
| 바뀌는 것 | 로그 문구, 작물·아이템 표시 이름, 도움말, 선택지, 헤더·패널 |
| 바뀌지 않는 것 | 명령어와 인자는 언어와 상관없이 영어다 (`/plant turnip`). 한국어 모드에서는 자동완성 목록에 한국어 이름을 같이 보여 준다 (`turnip  순무`) |
| 이미 찍힌 로그 | 그대로 두고, 새로 찍히는 로그부터 바뀐다 |

## 4. 시간

### 4.1 배속

게임 시간은 실제 시간에 배속을 곱해 흐른다. 배속과 계절 길이는 설정값 하나로 두고 프로토타입에서 맞춘다.

| 배속 | 게임 하루 | 계절 7일 | 계절 28일 | 느낌 |
| --- | --- | --- | --- | --- |
| **실제 1분 = 게임 1시간 (추천 초기값)** | 24분 | 약 2.8시간 | 약 11.2시간 | 30분~1시간마다 들여다보는 속도. 근무일 하루에 계절이 2~3번 바뀐다 (계절 7일 기준) |
| 실제 10초 = 게임 1시간 | 4분 | 28분 | 약 1.9시간 | 계속 붙어 있어야 하는 속도. 손으로 물 주기를 4분마다 해야 한다 |

### 4.2 빠른 게임 시계가 업무 중에도 괜찮은 이유

`생활 시뮬·RPG 메커니즘 조사.md`에서는 빠르게 흐르는 게임 시계를 업무용으로 맞지 않는다(✕)고 봤다. 방향 C에서는 다음 규칙으로 문제를 없앤다.

| 규칙 | 효과 |
| --- | --- |
| 물을 안 주면 **시들지 않고 성장만 멈춘다** | 자리를 비워도 손해가 없다 (P2) |
| 다 자란 작물은 수확할 때까지 그대로 기다린다 | 놓쳐도 잃는 것이 없다 |
| 계절은 **새로 심을 수 있는 작물만** 제한한다. 이미 심은 작물은 계절이 바뀌어도 끝까지 자란다 | 계절이 바뀌어도 망하지 않는다 |
| 행동은 명령어 한 줄이라 짧다 | 들여다보는 시간이 짧다 |

초반에 "24분마다 물 주기"가 귀찮은 것은 일부러 둔 장치다. **그 귀찮음이 스프링클러와 자동화를 사는 동기**가 된다.

### 4.3 꺼져 있던 시간: 상한까지 반영 (결정)

꺼져 있던 시간은 **상한까지만** 진행한다. 하룻밤(약 15시간)을 모두 반영하면 게임 37일이 지나가서 밸런스가 깨지기 때문이다. 상한은 판 안의 업그레이드 **Caretaker**와 영구 보너스 **Night Shift**(7.4)로 늘린다.

| Caretaker 레벨 | 상한 (실제 시간) | 게임 시간 (1분 = 1시간) | 버틸 수 있는 부재 |
| --- | --- | --- | --- |
| 0 (기본) | 2시간 | 5일 | 점심시간, 회의 |
| 1 | 4시간 | 10일 | 반나절 |
| 2 | 8시간 | 20일 | 근무 시간 하루 |
| 3 | 16시간 | 40일 | 하룻밤 (퇴근 → 출근) |
| 4 | 64시간 | 160일 | 주말 (금요일 퇴근 → 월요일 출근) |

(수치는 예시. 밸런스 단계에서 정한다.)

- 꺼져 있는 동안에는 **자동화만 일한다**. 스프링클러가 물을 주고, 규칙이 수확·심기·판매를 한다. 자동화가 없으면 물이 마르는 순간 성장이 멈춘다.
- 다시 켜면 시작 환영 상자에 부재 중 요약을 보여 준다. 예: `● Offline(2h → 5 days)` `⎿ harvested 120 · sold +3,400G`
- 앱이 켜져 있으면 화면이 잠겨 있어도(점심시간 등) 정상적으로 흐른다.

## 5. 핵심 루프

```
심기 → 물 주기 → 성장 → 수확 → 창고 → 판매 → 골드
  ↑                                           ↓
  └──── 투자: 땅 / 농기구 / 작물 / 자동화 / 창고 ────┘
```

### 5.1 땅 (구역 = 페이지)

| 단계 | 내용 |
| --- | --- |
| 시작 | 구역 1의 밭 일부만 열려 있다 |
| 칸·줄 구매 | 구역 1을 30칸(10칸 × 3줄)까지 넓힌다 |
| 새 구역 구매 | 구역 2, 3…이 페이지로 하나씩 추가된다. 갈수록 비싸진다 |

- 밭 좌표는 엑셀처럼 쓴다: 줄 `A`~`C`, 칸 `1`~`10`. 범위는 `A1:A4`, 한 줄 전체는 `A`, 구역 전체는 `all`.
- 다른 구역은 `f2.A1:A4`처럼 구역 번호를 붙인다 (문법은 초안). **명령어는 지금 보고 있는 구역과 상관없이** 어느 구역에든 쓸 수 있다. 페이지 이동은 "보기"용이다.

### 5.2 농기구: 한 번에 처리하는 범위

농기구를 업그레이드하면 **명령 하나로 처리할 수 있는 범위**가 넓어진다.

| 농기구 | 명령 | Lv1 | Lv2 | Lv3 |
| --- | --- | --- | --- | --- |
| 물뿌리개 | `/water` | 한 칸 | 한 줄 | 범위·구역 전체 |
| 씨앗 주머니 | `/plant` | 한 칸 | 한 줄 | 범위·구역 전체 |
| 낫 | `/harvest` | 한 칸 | 한 줄 | 범위·구역 전체 |

처음엔 `/water A1`을 여러 번 쳐야 하지만, 나중엔 `/water all` 한 번이면 된다. 레벨이 부족하면 로그에 `Requires watering can Lv3`처럼 알려 준다.

### 5.3 작물 (수치는 예시, 1분 = 1시간 기준)

| 작물 | 계절 | 씨앗 | 기준가 | 자라는 기간 | 실제 시간 |
| --- | --- | --- | --- | --- | --- |
| 순무 (turnip) | 봄 | 10G | 30G | 2일 | 48분 |
| 감자 (potato) | 봄 | 25G | 80G | 4일 | 1시간 36분 |
| 토마토 (tomato) | 여름 | 40G | 45G | 5일, 이후 3일마다 다시 수확 | 2시간, 이후 1시간 12분마다 |
| 옥수수 (corn) | 여름·가을 | 60G | 150G | 7일 | 2시간 48분 |
| 호박 (pumpkin) | 가을 | 100G | 380G | 10일 | 4시간 |
| 버섯 (mushroom) | 겨울 | 30G | 70G | 3일 | 1시간 12분 |

- 비싸고 오래 걸리는 작물일수록 많이 남지만, 오래 비워 두는 시간을 감수해야 한다.
- 다시 수확하는 작물(토마토)은 한 번 심으면 계속 나와서 자동화와 잘 맞는다.

### 5.4 시세

| 규칙 | 내용 |
| --- | --- |
| 기준가 + 매일 변동 | 매일 06시에 작물마다 시세가 오르내린다. 오래 보면 기준가 근처로 돌아온다 |
| 판매 압력 | 같은 작물을 한꺼번에 많이 팔면 값이 떨어진다. 여러 작물을 나눠 키우고 나눠 팔게 만든다 |
| 제철 아닌 작물 | 계절이 지난 작물은 시세가 오른다. 온실(후반)로 노릴 수 있다 |
| 창고 | 수확물을 보관하며 좋은 시세를 기다린다. 창고 용량이 업그레이드 대상이다 |
| 명령 | `/market`: 작물별 시세와 추세(▲▼)를 로그에 표로 보여 준다 |

### 5.5 계절

- 봄, 여름, 가을, 겨울. 작물마다 심을 수 있는 계절이 있다.
- 겨울에는 심을 작물이 적다. 온실을 사는 동기가 된다.
- 계절마다 도트의 풀·흙 색이 바뀐다.

## 6. 자동화: 장비형 + 규칙형

**장비가 기능을 열고, 규칙으로 조합한다.**

### 6.1 장비형

| 장비 | 효과 | 여는 규칙 행동 |
| --- | --- | --- |
| 스프링클러 | 매일 06시에 범위 안의 밭에 물을 준다. 밭 한 칸을 차지한다. Lv1 십자 4칸 → Lv2 주변 8칸 → Lv3 주변 24칸 | (자체 동작) |
| 자동 수확기 | 구역에 설치. 규칙에 따라 수확한다 | `harvest` |
| 자동 파종기 | 구역에 설치. 씨앗 재고로 빈 칸에 심는다 | `plant` |
| 출하함 | 창고의 작물을 판다 | `sell` |
| 자동 구매기 | 씨앗이 모자라면 산다 | `buy` |
| 온실 | 구역 하나를 계절과 상관없이 쓴다 | — |
| 농장 컨트롤러 | 규칙 슬롯 수와 규칙 검사 주기(게임 1시간마다 → 10분마다)를 늘린다 | (모든 규칙) |
| Caretaker | 꺼져 있던 시간의 반영 상한을 늘린다 (4.3) | — |

### 6.2 규칙형

형식은 `when <조건> do <행동>`이다 (초안).

```text
/auto add when f1 ready do harvest
/auto add when f1 empty do plant turnip
/auto add when price turnip >= 35 do sell turnip
/auto add when seed turnip < 10 do buy seed turnip 50
/auto list
/auto off 2
/auto del 2
```

- 규칙 행동을 쓰려면 그 행동을 여는 장비가 있어야 한다 (6.1).
- 규칙이 실행되면 로그에 `● Auto#1(harvest f1)` `⎿ turnip x30`처럼 남는다. 화면이 CI 파이프라인 로그처럼 보인다.
- 규칙 슬롯이 제한돼 있어서 어떤 규칙을 둘지 고르는 게 전략이 된다.

### 6.3 성장 단계

| 단계 | 플레이 | 주요 해금 |
| --- | --- | --- |
| 초반 | 손으로 심고, 물 주고, 수확하고, 판다 | 물뿌리개 Lv2, 칸·줄 추가, 감자 |
| 중반 | 스프링클러로 물 주기를 자동화한다 | 구역 2, 자동 수확기, 출하함, 규칙 슬롯, Caretaker |
| 후반 | 규칙으로 심기 → 수확 → 판매를 완전히 자동화한다 | 자동 파종기, 자동 구매기, 시세 규칙, 온실 |
| 무한 | 지수 비용 업그레이드, 고급 작물 등급, 기록 경쟁 | 프레스티지 (7.4) |

## 7. 무한 성장: 기록·랭킹·프레스티지

엔딩이 없는 대신 **지난 판의 내 기록을 깨는 것**을 장기 목표로 둔다. 사용자 제안(2026-11-26): 날짜별 자산을 랭킹·스코어로 남기면 프레스티지가 의미를 갖는다.

### 7.1 성장 장치

| 장치 | 내용 |
| --- | --- |
| 지수 비용 | 땅, 장비 레벨, 규칙 슬롯 비용이 지수로 오른다 |
| 큰 숫자 표기 | `1.2K`, `3.4M`, `5.6B`, `7.8T` … |
| 도감·업적 | 작물 도감(첫 수확, 누적 수확량 단계), 업적 |

### 7.2 점수 = 총자산 (Net worth)

| 구성 | 계산 |
| --- | --- |
| 골드 | 그대로 |
| 창고 작물 | 수량 × 현재 시세 |
| 씨앗 재고 | 수량 × 구매가 |
| 땅·장비·농기구 | 구매에 쓴 금액 합계 |

땅이나 장비를 사도 점수가 떨어지지 않도록, 투자한 금액을 자산으로 센다.

### 7.3 기록과 랭킹

**판(run)**은 프레스티지와 프레스티지 사이의 농장 하나다. 판마다 Day 1부터 다시 센다.

| 기록 | 기준 | 용도 |
| --- | --- | --- |
| 체크포인트 기록 | 판마다 게임 날짜 Day 7, 14, 28, 56, 112 … (2배씩)에 닿은 순간의 총자산 | 판끼리 **같은 날짜에서** 비교한다. 스피드런의 구간 기록과 같다 |
| 일별 기록 | 실제 날짜마다 그날 마지막 총자산과 그날 번 돈 | 오늘 얼마나 벌었는지, 가장 많이 번 날 |
| 최고 기록 | 모든 판을 통틀어 가장 높은 총자산 | 전체 목표 |

- 체크포인트에 닿으면 지난 최고 기록과 비교해 보여 준다: `● Checkpoint(Day 28)` `⎿ 310K · best 280K (run #2) · ▲ 30.0K NEW BEST`
- 랭킹은 내 기록끼리만 비교한다 (서버, 온라인 없음).

```text
> /records
● Records(run #3 · Day 31)
  ⎿  Day    Best           Run #3     Diff
     7      12.4K (#2)     15.1K      ▲ 2.7K
     14     58.0K (#2)     61.3K      ▲ 3.3K
     28     280K  (#2)     310K       ▲ 30K
     56     2.1M  (#1)     -
     112    8.2M  (#1)     -

> /rank
● Rank(peak net worth)
  ⎿  #    Run    Peak      Days    Ended
     1    #1     8.9M      130     2026-12-04
     2    #2     1.4M      45      2026-12-08
     3    #3     310K      31      (current)
```

### 7.4 프레스티지: Lupin Bloom (제안)

- **컨셉**: 루피너스(lupin)는 실제로 땅을 기름지게 하는 녹비 작물로 쓰인다. 프레스티지를 하면 농장 전체에 루피너스를 피웠다가 갈아엎고, 그 대가로 땅의 **비옥도(Fertility)**가 영구히 오른다. 게임 이름과도 이어진다.
- **진행**: `/prestige` → 미리보기(얻을 Fertility, 이번 판 기록 요약) → 번호 선택지로 두 번 확인 → 루피너스가 피는 도트 장면 → 새 판 시작 (run #N+1, Day 1, 봄).

| 초기화되는 것 | 남는 것 |
| --- | --- |
| 골드, 땅, 작물, 창고, 씨앗, 장비, 농기구 레벨, 시세 상태, 게임 날짜 | 기록·랭킹, 도감·업적, Fertility와 영구 보너스, 자동화 규칙 문장(장비를 다시 사면 바로 동작), 설정(언어 등) |

- **Fertility 계산 (예시)**: 이번 판 최고 총자산이 클수록 많이 받되 점점 덜 늘어난다. 예: `floor(sqrt(peak / 100K))` → 최고 8.9M이면 9, 310K면 1.
- **영구 보너스** (`/perks`, 이름과 수치는 예시):

| 보너스 | 효과 (레벨당) |
| --- | --- |
| Rich Soil | 성장 속도 +5% |
| Market Sense | 판매 가격 +3% |
| Head Start | 시작 골드 증가 |
| Old Fields | 시작할 때 열린 밭 칸 증가 |
| Night Shift | 꺼져 있던 시간의 반영 상한 증가 |
| Rule Memory | 규칙 슬롯 +1 |
| Seasoned Hands | 농기구 시작 레벨 +1 |

**프레스티지가 의미 있는 이유**: 영구 보너스 덕분에 다음 판은 같은 체크포인트에 더 많은 자산으로 도달한다. 지난 기록을 깨는 재미가 생기고, **언제 프레스티지할지**(지금 다시 시작할지, 더 키울지)가 전략이 된다.

## 9. 페이지 전환

| 방법 | 예시 | 메모 |
| --- | --- | --- |
| 명령어 | `/field 2`, `/field next` | 항상 된다 |
| 키보드 | `PgUp` / `PgDn` | 입력창에 커서가 늘 있으니, 글자 입력과 겹치지 않는 키를 쓴다. `←` `→`는 입력창 커서 이동에 쓴다 |
| 마우스 | 농장 영역 양옆의 `◀` `▶` 클릭 | 지원한다 (사용자 결정). Windows Terminal에서 받는 방식은 프로토타입에서 확인한다 (`기술 스택 조사.md` 5절) |
| 위치 표시 | 아래 테두리의 `● ○ ○`, 위 테두리의 `field 1/3` | |

- 구역 하나의 크기는 고정(10칸 × 3줄)이다. 창 크기에 따라 칸 수가 바뀌면 농장 배치가 흐트러지기 때문이다.
- 구역이 많아지면 `/map`으로 전체 요약을 본다.

## 10. 설계 원칙 확인

| 원칙 | 방향 C에서 |
| --- | --- |
| P1 소리·큰 움직임 없음 | 무음. 움직이는 것은 스피너와 작물 단계 변화 정도다 |
| P2 언제든 멈춤 | 시들지 않음, 다 자란 작물은 기다림, 명령어 한 줄짜리 조작 |
| P3 업무 화면처럼 보임 | AI 코딩 도구로 작업하는 화면처럼 보인다. `/hide`로 농장 영역을 접으면 로그와 입력창만 남는다. 영어 기본 문구도 도구 로그처럼 보인다 |
| P4 보스키 | 전역 단축키로 평범한 PowerShell 프롬프트 화면으로 바꾼다 (`기술 스택 조사.md` 4.5) |

방향 C의 위장은 지금까지 나온 방향 중 가장 강하다. 개발자가 AI 코딩 도구에 명령을 치는 모습 자체가 업무로 보이고, 실제로 타이핑을 하고 있기 때문이다. 다만 농장 영역이 1/3보다 커지고 도트로 그려지는 만큼, 그 영역은 `/hide`와 보스키로 가린다.
