# 기술 스택 조사

작성일: 2026-11-26 · 기준 문서: `아이디어 정리.md`

방향 A(바탕화면 생태계), 방향 B(PowerShell 도트 게임), 방향 C(명령어 농장 타이쿤)를 만들 기술을 비교한 결과다. **아직 결정 전**이며, 6절은 추천안이다. 방향 C는 B와 같은 터미널 렌더링(4절)을 쓰고, C에만 필요한 것은 5절에 있다.

## 1. 요구 조건

### 공통

- Windows 11에서 동작한다 (이 PC는 빌드 26200).
- 회사 PC는 설치 권한이 없을 수 있다. **설치 없이 실행되는 단일 exe**가 유리하다.
- 오래 켜 두므로 메모리와 CPU를 적게 쓴다.
- 전역 단축키(보스키)를 쓴다.

### 방향 A: 바탕화면 생태계

- 바탕화면 아이콘 뒤, 배경 위 레이어에 그린다.
- 트레이 아이콘, 트레이 메뉴, 알림을 쓴다.
- 투명·테두리 없는 작은 창을 띄울 수 있다 (작업표시줄 펫).

### 방향 B: PowerShell 도트 게임

- 진짜 PowerShell 탭(Windows Terminal) 안에서 실행한다.
- 터미널 글자로 도트를 그린다 (트루컬러, 유니코드 블록 문자).
- 키보드로 입력받고, 화면이 깜빡이지 않게 갱신한다.
- 보스키를 누르면 즉시 평범한 프롬프트 화면으로 바뀐다.

### 방향 C: 명령어 농장 타이쿤

- 방향 B의 요구 조건을 모두 포함한다.
- 명령어를 입력하는 동안에도 농장 영역과 시계가 계속 갱신된다.
- 화면 양옆 `◀` `▶`를 마우스로 클릭할 수 있으면 좋다.
- 꺼져 있던 시간을 다시 켤 때 계산한다.
- 무한 성장이므로 아주 큰 숫자를 다룬다.

## 3. 바탕화면 레이어(아이콘 뒤)에 그리는 방법 (방향 A)

라이브 배경화면 프로그램들이 쓰는 **WorkerW 방식**이다.

1. `FindWindow("Progman", null)`로 바탕화면 창을 찾는다.
2. `SendMessageTimeout(progman, 0x052C, ...)`을 보내면 탐색기가 아이콘 뒤에 `WorkerW` 창을 만든다.
3. `EnumWindows`로 아이콘 창(`SHELLDLL_DefView`)을 가진 창을 찾고, 그 다음 `WorkerW`를 찾는다.
4. 게임 창을 `SetParent`로 그 `WorkerW`의 자식으로 넣는다. 그러면 아이콘 뒤, 배경 위에 그려진다.

| 주의할 점 | 내용 |
| --- | --- |
| Windows 11 24H2 이후 구조 변경 | 바탕화면 창 구조가 바뀌어 3단계의 `WorkerW`를 찾는 방법이 달라졌다. 이 PC(빌드 26200)에서 직접 확인해야 한다 **(확인 필요)** |
| 마우스 입력 | 아이콘 창이 위에 덮여 있어서 배경 레이어 창은 클릭을 받기 어렵다. 조작은 트레이와 작은 팝업으로 한다 |
| 탐색기 재시작 | `explorer.exe`가 다시 시작되면 `WorkerW`가 사라진다. `TaskbarCreated` 메시지를 받으면 다시 붙이고 트레이 아이콘도 다시 등록한다 |
| 대안 | 배경 레이어가 안 되면, 항상 맨 아래(`HWND_BOTTOM`)에 붙는 테두리 없는 창으로 대신한다. 이 경우 바탕화면 아이콘보다 위에 그려진다 |

## 4. 터미널 도트 렌더링 (방향 B)

### 4.1 반쪽 블록 도트

터미널 글자 한 칸은 가로:세로가 약 1:2다. 위 반쪽 블록 `▀`(U+2580)을 찍고 **글자색 = 위 픽셀, 배경색 = 아래 픽셀**로 칠하면, 한 칸이 거의 정사각형인 픽셀 2개가 된다. 색은 24비트 트루컬러로 지정한다 (Windows Terminal 지원).

### 4.2 해상도

| 터미널 크기 (칸) | 도트 해상도 (픽셀) | 8×8 타일 기준 |
| --- | --- | --- |
| 120×30 (Windows Terminal 기본 창) | 120×60 | 15×7 |
| 약 210×54 (1080p 최대화, 기본 글꼴) **(확인 필요)** | 약 210×108 | 약 26×13 |

- 상태 패널과 로그 영역을 빼면 맵 영역은 더 작다. 카메라가 캐릭터를 따라가는 스크롤 맵으로 만든다.
- 글꼴을 줄이면(`Ctrl+-`) 해상도가 올라간다.
- 텍스트 모드는 타일 하나가 글자 1개 + 공백(가로 2칸)이라, 120×30 창에서 60×30 타일을 보여 줄 수 있다.

### 4.3 쓰는 VT 제어 문자

| 기능 | 제어 문자 |
| --- | --- |
| 대체 화면 버퍼 진입 / 복귀 | `ESC[?1049h` / `ESC[?1049l` |
| 커서 숨김 / 표시 | `ESC[?25l` / `ESC[?25h` |
| 커서 이동 | `ESC[{줄};{칸}H` |
| 글자색 / 배경색 (트루컬러) | `ESC[38;2;{r};{g};{b}m` / `ESC[48;2;{r};{g};{b}m` |
| 색 초기화 | `ESC[0m` |
| 화면 지우기 | `ESC[2J` (스크롤 기록까지 지우려면 `ESC[3J` 추가) |
| 창(탭) 제목 | `ESC]0;{제목}BEL` |

### 4.4 구현 메모

| 항목 | 내용 |
| --- | --- |
| 인코딩·VT 켜기 | .NET Framework 콘솔은 직접 켜야 한다. `Console.OutputEncoding`을 UTF-8로 바꾸고, `SetConsoleMode`로 `ENABLE_VIRTUAL_TERMINAL_PROCESSING`을 켠다. Windows Terminal에서는 기본으로 켜져 있지만, 옛 콘솔 창(conhost)에서도 돌도록 켠다 |
| 깜빡임 방지 | 한 프레임을 문자열 하나로 모아 한 번에 쓴다. 이전 프레임과 비교해 바뀐 칸만 다시 그린다 |
| 갱신 주기 | 턴제라 키를 누를 때만 다시 그린다. 물결 같은 작은 애니메이션만 느린 주기(예: 1초)로 갱신한다 (P1) |
| 입력 | `Console.ReadKey(true)` (화면에 글자가 찍히지 않는다) |
| 전역 보스키 | 별도 스레드에서 `RegisterHotKey`를 등록하고 메시지 루프(`GetMessage`)를 돌린다. 터미널에 포커스가 없어도 동작한다 |
| 창 크기 변경 | 그릴 때마다 `Console.WindowWidth`, `Console.WindowHeight`를 확인해 배치를 다시 잡는다 |
| 탭 제목 | 시작할 때 PowerShell 기본 제목처럼 바꿔 둔다 |

### 4.5 보스키 화면

1. 게임을 시작할 때 원래 화면을 지우고 평범한 프롬프트 한 줄(예: `PS C:\dev\git\...>`)을 찍어 둔다. 게임을 실행한 명령이 보이지 않게 하기 위해서다.
2. 게임은 대체 화면 버퍼에서 돈다.
3. 보스키를 누르면 대체 화면 버퍼에서 빠져나온다. 1에서 찍어 둔 프롬프트만 보이는, 입력을 기다리는 PowerShell 화면이 된다.
4. 다시 누르면 대체 화면 버퍼로 돌아가 이어서 한다. 숨어 있는 동안 캐릭터 행동은 멈추고, 세계 시계(작물 성장)는 계속 흐른다.

실제로 어떻게 보이는지는 프로토타입에서 확인한다 **(확인 필요)**.

## 5. 방향 C에만 필요한 것

| 항목 | 내용 |
| --- | --- |
| 입력창 직접 구현 | `Console.ReadLine`은 입력이 끝날 때까지 프로그램을 멈춰서, 그동안 농장과 시계를 갱신할 수 없다. `Console.KeyAvailable`로 키를 확인하고 `Console.ReadKey(true)`로 읽는 한 줄 편집기를 직접 만든다 (글자 입력, 지우기, `←` `→`, `Home` `End`, `↑` `↓` 이전 명령, `Tab` 자동완성, `Enter`) |
| 화면 배치 | 헤더 1줄 + 농장 영역 고정 14줄 + 로그(남는 줄) + 입력창 3줄 + 안내 1줄. 최소 120×30 (`명령어 농장 컨셉 분석.md` 3.1) |
| 갱신 주기 | 게임 시계가 흐르므로 실제 1초마다 확인하고, 바뀐 칸만 다시 그린다. 작물 단계는 자주 바뀌지 않아서 실제로 다시 그리는 양은 적다 |
| 마우스 클릭 (`◀` `▶`) | 지원한다 (사용자 결정 2026-11-26). 두 가지 방법이 있다. ① `ReadConsoleInput` + `ENABLE_MOUSE_INPUT`으로 마우스 이벤트 받기 ② VT 마우스 모드(`ESC[?1000h`, `ESC[?1006h`)를 켜고 입력을 VT 문자열로 읽기. Windows Terminal에서 어느 쪽이 되는지 프로토타입에서 확인한다 **(확인 필요)**. 둘 다 안 되면 명령어와 `PgUp`/`PgDn`만 쓴다 |
| 글자 폭 | `▀` `◀` `▶` `●` 같은 문자는 글꼴이나 설정에 따라 2칸으로 그려질 수 있다 (동아시아 "모호한 폭" 문자). **1칸으로 그려지는 것을 전제로 한다** (사용자 결정 2026-11-26). Windows Terminal 기본 설정에서는 1칸으로 그리는 것으로 알고 있지만 프로토타입에서 확인한다 **(확인 필요)**. 2칸이면 `◀` `▶` `●`는 ASCII(`<` `>` `o`)로 바꾸고, `▀`는 도트 방식 자체를 다시 검토한다 |
| 문구 언어 | 화면에 보이는 모든 문구를 문자열 표(키 → 영어·한국어 문구)에서 꺼내 쓴다. 기본은 영어, `/config lang ko`로 바꾼다. 명령어 이름과 인자는 표에 넣지 않는다 (항상 영어) |
| 한글 폭 | 한글은 한 글자가 2칸이다. 한국어 모드에서 패널 정렬과 줄바꿈은 글자 수가 아니라 화면 폭(한글·전각 문자 = 2칸)으로 계산한다 |
| 기록 저장 | 기록·랭킹(체크포인트, 일별 기록, 판 목록)은 세이브와 다른 파일에 저장한다. 프레스티지로 세이브가 초기화되거나 세이브 파일이 깨져도 기록은 남게 하기 위해서다 |
| 꺼져 있던 시간 계산 | 저장할 때 실제 시각을 함께 기록한다. 다시 켜면 (지금 − 저장 시각) × 배속만큼 게임 1시간 단위로 시뮬레이션해서 따라잡는다 (상한 적용). 시세 변동 같은 난수는 시드를 저장해 같은 결과가 나오게 한다 |
| 저장 | 일정 주기마다, 그리고 종료할 때 저장한다. 회사 PC가 강제로 꺼질 수 있으니 임시 파일에 쓴 뒤 바꿔치기한다 (쓰는 도중 꺼져도 세이브가 깨지지 않게) |
| 큰 숫자 | 골드와 수량은 `double`로 다루고 `1.2K`, `3.4M`처럼 줄여 표시한다. `long`은 약 9.2×10^18에서 넘친다 |
| 명령어 해석 | `/명령 인자…` 형식. 범위 문법(`A1:A4`, `A`, `all`, `f2.A1:A4`)과 규칙 문법(`when … do …`)을 해석한다 |

## 6. 결정 (2026-11-26)

**C# + .NET Framework 4 내장 컴파일러**로 정했다 (사용자 결정). 이 PC에는 .NET Framework 4.8.1과 `csc.exe`(C# 5)가 있고 Windows Terminal도 설치되어 있다. 설계는 `../1.architecture/03_시스템 설계.md`.

- **방향 C·B**: 콘솔 앱(`/target:exe`)으로 빌드해 PowerShell 탭에서 실행한다.
- **방향 A**: 같은 도구로 WinForms 앱을 만든다. 콘솔 앱에서도 트레이 아이콘이나 창을 띄울 수 있어서, 나중에 관상 모드(`아이디어 정리.md` B10)를 같은 프로그램에 붙일 수 있다.
- **공통 장점**: 회사 PC에서 개발 도구도 실행 환경도 설치할 필요가 없다. Win32를 바로 호출할 수 있다. `merry-christmas`에서 같은 빌드 방식을 이미 써 봤다.
- **단점**: C# 5 문법까지만 쓸 수 있다. 방향 A는 GDI+라 화려한 그래픽에 한계가 있다 (방향 B는 터미널이 그리므로 해당 없음).

차선: 방향 A에서 그래픽 표현력이 중요해지면 Tauri 2. 방향 B에서 PowerShell 스크립트는 실행 정책과 속도 문제로 권하지 않는다.
