# 위장형 게임 장르 조사

작성일: 2026-11-26 · 기준 문서: `아이디어 정리.md`

업무 시간에 들키지 않고 할 수 있는 게임 장르를 비교한 결과다. 설계 원칙 P1~P4는 `아이디어 정리.md` 4절에 있다.

처음에는 바탕화면 기반 장르 5종(3.1~3.5)을 비교했다. 이후 사용자가 "PowerShell 환경 같은 느낌의 도트 RPG, 동물의 숲·스타듀 밸리 같은 생활 시뮬"을 추가로 요청해서 3.6~3.8을 더하고 결론을 다시 냈다.

## 3. 장르별 상세

### 3.1 바탕화면 생태계 (방치형)

- **컨셉**: 바탕화면 배경 자체가 작은 세계다. 시간이 지나면 개체가 늘고, 구조물이 생기고, 환경이 바뀐다.
- **숨는 방법**: 바탕화면 아이콘 뒤, 배경 위 레이어에 그린다 (`기술 스택 조사.md` 3절). 업무 창이 덮고 있으면 보이지 않는다. 확인할 때는 `Win+D`(바탕 화면 보기)를 누르거나 작업표시줄 오른쪽 끝을 클릭한다.
- **세계 후보**: 개미굴, 수족관, 미니 마을, 우주 정거장
- **장점**: 원래 숨어 있다. 방치형이라 업무 패턴에 맞는다. 바탕화면을 가장 직접적으로 쓰는 장르다.
- **단점**: 바탕화면을 보는 순간에는 노출된다. 배경 레이어는 마우스 입력을 받기 어려워서 조작을 따로 만들어야 한다 (트레이로 해결). 배경 레이어 구현이 Windows 버전의 영향을 받는다. 관상 위주라 깊이가 얕다.

### 3.2 작업표시줄 펫

- **컨셉**: 작업표시줄 바로 위에 얇은 투명 창을 띄우고, 그 위를 캐릭터가 걸어 다니며 자원을 모은다. 가끔 클릭해서 수확하거나 돌본다.
- **장점**: 늘 보여서 상태 확인이 쉽다. 구현이 비교적 쉽다 (투명·항상 위 창).
- **단점**: 늘 보이니 다른 사람 눈에도 띈다. 움직임을 작고 느리게 해야 P1을 지킨다.

### 3.3 트레이 낚시

- **컨셉**: 트레이 아이콘이 미세하게 바뀌면 입질이 온 것이다. 클릭하면 낚고, 결과는 윈도우 기본 알림처럼 보여 준다.
- **장점**: 가장 안 보인다. 구현이 가장 쉽다.
- **단점**: 표현 수단이 16×16 아이콘과 알림뿐이라 깊이가 얕다. 단독 게임보다는 다른 장르의 상호작용 수단으로 쓰기 좋다.

### 3.4 아이콘 디펜스

- **컨셉**: 실제 바탕화면 아이콘 위치를 기지로 삼고, 화면 전체에 투명 오버레이를 띄워 적이 기어 오게 한다.
- **장점**: 재미가 가장 크다. "내 바탕화면이 전장"이라는 컨셉이 가장 강하다.
- **단점**: 화면 전체를 쓰고 실시간 대응이 필요해서 P1~P3에 모두 어긋난다. 실제 아이콘 위치를 읽어 와야 해서 구현도 어렵다.

### 3.5 로그 위장 RPG

- **컨셉**: 터미널이나 IDE 콘솔에 Spring Boot 로그처럼 보이는 줄이 흘러가며 전투와 탐험이 진행된다. 개발자 화면에서 가장 자연스럽다.
- **장점**: 은밀도가 가장 높다. 그래픽이 없어 가장 빨리 만들 수 있다.
- **단점**: 바탕화면 기반이 아니다. 표현이 텍스트뿐이다.

```text
2026-11-26 14:08:01.123  INFO 4820 --- [battle-svc-1] c.w.b.BattleService  : Goblin hit: dmg=12, hp=38/50
2026-11-26 14:08:01.456  WARN 4820 --- [battle-svc-1] c.w.b.BattleService  : HP low: ratio=0.30, threshold=0.30
2026-11-26 14:08:02.001  INFO 4820 --- [loot-svc-2]   c.w.l.LootService    : Item acquired: id=sword_02, rarity=RARE
```

### 3.6 PowerShell 위장 (3.7, 3.8 공통)

- **컨셉**: 게임이 **진짜 PowerShell 탭(Windows Terminal) 안에서** 돈다. 개발자 PC에는 터미널 창이 늘 떠 있으니 창 자체가 자연스럽다. 조작은 키보드만 쓴다. 타이핑하는 모습이 업무처럼 보인다.
- **도트 표현**: 반쪽 블록 문자(`▀`)의 글자색과 배경색으로 한 칸에 픽셀 2개를 그린다 (`기술 스택 조사.md` 4절).
- **위장 3단계**: 상황에 따라 한 키로 바꾼다.

| 단계 | 상황 | 화면 |
| --- | --- | --- |
| 1. 도트 모드 | 혼자 있을 때 | 도트 맵 + 오른쪽 상태 패널 + 아래 로그. k9s, htop 같은 TUI 도구처럼 배치한다 |
| 2. 텍스트 모드 | 주변에 사람이 있을 때 | 같은 화면을 글자 타일과 로그로 보여 준다. 색이 들어간 명령 출력처럼 보인다 |
| 3. 보스키 | 누가 다가올 때 | 게임 화면이 사라지고 평범한 PowerShell 프롬프트만 남는다 |

도트 모드 배치 예시 (패널 문구는 예시이며, 화면 문구 언어는 미정):

```text
┌─ field ─────────────────────────────┐┌─ status ───────────┐
│                                     ││ day 12  14:08 sunny│
│  half-block (▀) pixel map           ││ stamina ████████░░ │
│  8x8 tiles, camera follows player   ││ gold    1,240      │
│                                     │├─ inventory ────────┤
│                                     ││ turnip seed   x12  │
│                                     ││ watering can  Lv2  │
└─────────────────────────────────────┘└────────────────────┘
[14:08:01] INFO  crop.Turnip     watered: plot=(3,4)
[14:08:05] INFO  crop.Turnip     ready in 2h 10m
[14:08:09] WARN  stamina         low: 20%
```

텍스트 모드 예시 (`@` 나, `.` 땅, `"` 풀, `T` 나무, `~` 물, `#` 울타리, `*` 다 자란 작물, `v` 새싹):

```text
 . . " " . T T . ~ ~ ~ ~     day 12  14:08 sunny
 . @ . . . T . . ~ ~ ~ ~     stamina 80/100
 # # # # # . . . . ~ ~ ~     gold    1,240
 # * * v v # . " . . ~ ~
 # * * v v # . . . . . .
[14:08:01] INFO  crop.Turnip     watered: plot=(3,4)
[14:08:05] INFO  crop.Turnip     ready in 2h 10m
```

- **장점**: 개발자에게 가장 자연스러운 창이다. 생활 시뮬, RPG처럼 깊이 있는 장르를 담을 수 있다. 로그 위장 RPG(3.5)의 장점을 텍스트 모드와 로그로 흡수한다.
- **단점**: 도트 모드는 정면에서 보면 게임인 게 보인다 (텍스트 모드와 보스키로 보완한다). 화면 해상도가 터미널 글자 수에 묶여 낮다.

### 3.7 터미널 도트 생활 시뮬 (농장·마을 타이쿤)

- **컨셉**: 동물의 숲, 스타듀 밸리 계열의 장르와 메커니즘을 가져온다. 이름, 캐릭터, 그래픽은 오리지널로 만든다. 메커니즘 상세는 `생활 시뮬·RPG 메커니즘 조사.md`에 있다.
- **핵심 변형**: 세계(작물, 날짜, 계절)는 실제 시계로 흐르고, 캐릭터 행동은 턴제다. 하루 행동력이 정해져 있다.
- **장점**: 보고 있지 않아도 자라는 방치형 진행과 짧은 세션이 업무 패턴에 가장 잘 맞는다. 도감, 마을 확장 같은 장기 목표가 많아 오래 할 수 있다.
- **단점**: 작물, 주민, 아이템, 도트 등 만들 콘텐츠가 가장 많다.

### 3.8 터미널 도트 RPG (턴제 던전)

- **컨셉**: 도트 맵 탐험, 턴제 전투, 로그라이크식 랜덤 층.
- **장점**: 턴제라 전투 중에도 언제든 멈출 수 있다. 한 판이 짧다.
- **단점**: 방치형 진행이 없어서, 단독으로는 "보고 있지 않아도 자라는" 재미가 없다. 생활 시뮬과 묶으면 보완된다.

## 4. 결론 (A·B 비교)

> 이 결론은 5절에서 방향 C 추가로 갱신했다.

1차 결론은 "바탕화면 생태계 + 트레이 상호작용 + 보스키"였다. 사용자 추가 요청 후 두 방향을 다시 비교했다.

| 항목 | A. 바탕화면 생태계 | B. PowerShell 도트 생활 시뮬 + 던전 |
| --- | --- | --- |
| 은밀도 | 평소에는 창 뒤에 숨어 있고, 바탕화면을 볼 때만 노출된다 | 터미널 창이라 자연스럽다. 도트 모드는 정면에서 보면 노출되므로 텍스트 모드와 보스키로 보완한다 |
| 재미·깊이 | 관상 위주라 얕다 | 농사, 경제, 주민, 던전으로 깊다 |
| 조작 | 트레이 메뉴 (마우스) | 키보드만 |
| 구현 위험 | Windows 11 24H2 이후 배경 레이어 구조가 바뀌었다 (확인 필요) | 낮다. 터미널 출력만 쓴다 |
| 만들 양 | 적다 | 많다 (콘텐츠) |

**추천: B. PowerShell 도트 생활 시뮬(메인) + 턴제 던전(서브) + 위장 3단계**

- 사용자가 원하는 깊이(RPG, 타이쿤)를 담을 수 있다.
- 실제 시계로 자라는 세계(방치형)와 턴제 행동(언제든 멈춤)이 업무 패턴에 맞는다.
- 개발자 화면에서 터미널은 가장 자연스러운 창이다.
- Windows 바탕화면 구조에 기대지 않아서 구현 위험이 낮다.

A는 버리지 않는다. 같은 세이브의 농장을 바탕화면 레이어에 띄우는 **관상 모드**로 나중에 붙인다 (`아이디어 정리.md` B10).

B가 설계 원칙을 지키는 방법:

| 원칙 | 지키는 방법 |
| --- | --- |
| P1 소리·큰 움직임 없음 | 무음. 키를 누를 때만 다시 그리고, 물결 같은 작은 애니메이션만 느리게 움직인다 |
| P2 언제든 멈춤 | 턴제 행동, 실제 시계 성장, 방치 페널티 없음 |
| P3 업무 화면처럼 보임 | 진짜 PowerShell 탭, TUI 도구 같은 배치, 로그형 메시지, 텍스트 모드 |
| P4 보스키 | 대체 화면 버퍼를 빠져나와 평범한 프롬프트 화면을 보여 준다. 전역 단축키라 다른 창에 포커스가 있어도 동작한다 |

장르별 처리:

| 터미널 도트 생활 시뮬 | 메인 |

| 로그 위장 RPG | 텍스트 모드와 로그형 메시지로 흡수 |
| 바탕화면 생태계 | 관상 모드 (나중에) |

| 작업표시줄 펫 | 보류 |

## 5. 방향 C 추가 (2026-11-26)

사용자가 새 방향을 직접 기획했다. **Claude Code 같은 화면에서 영어 슬래시 명령어로 진행하는 농사 전용 타이쿤**이다. 상세는 `명령어 농장 컨셉 분석.md`에 있다.

방향 B를 농사로 좁히고, 캐릭터 이동 대신 명령어로 조작하는 형태다.

| 항목 | A. 바탕화면 생태계 | B. PowerShell 도트 생활 시뮬 | C. 명령어 농장 타이쿤 |
| --- | --- | --- | --- |
| 은밀도 | 평소 창 뒤에 숨음. 바탕화면을 볼 때 노출 | 터미널 창. 도트 모드는 정면에서 노출 | AI 코딩 도구 작업 화면처럼 보임. 농장 영역은 `/hide`로 접음 |
| 재미·깊이 | 얕음 (관상) | 깊음 (농사·주민·던전) | 깊음 (경제·시세·자동화 설계) |
| 조작 | 트레이 메뉴 (마우스) | 키보드로 캐릭터 이동 | 키보드로 명령어 입력 |
| 구현 위험 | 배경 레이어 구조 변경 (확인 필요) | 낮음 | 낮음 |
| 만들 양 | 적음 | 많음 (주민 대사, 전투, 캐릭터 도트) | 중간 (작물 도트, 명령어 해석기, 경제 밸런스) |

**추천: C**
