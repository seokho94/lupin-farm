## 3. 저장 형식

두 파일 모두 이전 형식을 그대로 읽는다. 빠진 값은 `Normalize()`가 채운다.

`save.json` (현재 판, 더한 필드):

```json
{
  "PeakNetWorth": 330000.0, "PeakDay": 30,
  "Checkpoints": { "7": 15100.0, "14": 61300.0, "28": 310000.0 },
  "Earned": 42000.0,
  "Harvested": { "turnip": 120 },
  "Perks": { "rich-soil": 2 },
  "AutoDay": 31, "AutoMask": 7, "FullAuto": true,
  "Fields": [ { "Plots": [ { "Crop": "turnip", "Growth": 100, "Need": 2619 } ] } ]
}
```

`profile.json` (판을 넘어 남는 것, 더한 필드):

```json
{
  "Fertility": 8,
  "Perks": { "rich-soil": 2, "night-shift": 1 },
  "Runs": [ { "Run": 1, "StartedAt": "2026-11-27", "EndedAt": "2026-12-04", "Peak": 8900000.0, "PeakDay": 120,
              "LastDay": 130, "Fertility": 9, "Checkpoints": { "7": 11800.0 }, "Harvested": { "turnip": 900 } } ],
  "Daily": [ { "Date": "2026-12-10", "Run": 3, "NetWorth": 310000.0, "Earned": 42000.0, "EarnedBase": 0.0 } ],
  "Dex": { "turnip": { "First": "2026-11-27", "FirstRun": 1, "Total": 1820 } },
  "Achievements": { "first-harvest": "2026-11-27" }
}
```

| 필드 | 설명 |
| --- | --- |
| `Plot.Need` | 다 자라는 데 필요한 성장 분. 심을 때 정한다. 0이면 작물 기본값 (M3 세이브의 작물) |
| `Perks` (save) | 프로필 보너스의 사본. 엔진·시세·규칙이 프로필 없이 쓴다. 불러올 때와 살 때 프로필에서 맞춘다 |
| `Earned` | 이번 판 판매 수입 합계 (손·규칙). 일별 기록 = `Earned − EarnedBase` |
| `Harvested` | 이번 판 작물별 수확 수. 판 기록의 `Harvested`와의 차이만큼 도감 누적을 늘린다 |
| `Runs[].Harvested` | 마지막으로 도감에 옮긴 이번 판 수확 수 |

## 4. 기록 흐름

- 게임 로직 안(엔진·규칙·명령)은 `GameState`에만 쌓는다: 판 최고, 체크포인트, 판매 수입, 수확 수, `full-auto` 값.
- 화면이 `Records.Sync(state, profile, 오늘)`로 프로필에 옮긴다. 부르는 때: 시작(꺼져 있던 시간을 반영하기 전과 후), 실시간 진행 뒤, 명령 앞뒤(선택지 결과 포함), 프레스티지 직전.
- `Sync`가 하는 일: 판 최고 갱신 → 판 기록(최고·마지막 날·체크포인트) → 일별 기록 → 도감(처음 수확·별 증가 이벤트) → 업적(조건 검사, 이벤트).
- 하루 끝(게임 분 = d × 1440)에 엔진이 `Records.DayEnd`: 판 최고 갱신, Day d가 체크포인트면 그 순간 총자산을 기록하고 진행 결과에 날짜를 넣는다. 시세 갱신보다 먼저다.
- 체크포인트 이벤트(`● Checkpoint(Day 28)`)는 화면이 진행 결과로 만든다. 꺼져 있던 동안 지나간 것은 시작 상자(또는 절전 복귀 이벤트)의 줄로 넣는다. `NEW BEST`면 업적 `new-best`.

| 값 | 식 |
| --- | --- |
| 총자산 | 골드 + Σ 창고 × `Market.Price`(판매 압력 없음, 계절·Market Sense 포함) + Σ 씨앗 × 씨앗값 + 투자액 |
| 지난 최고 | 현재 판을 뺀 판 기록들의 같은 체크포인트 중 최댓값 |
| Fertility | `floor(sqrt(판 최고 / 100,000))` |
| 필요 성장 분 | `올림(성장 분 / (1 + 0.05 × rich-soil))` (나눠떨어지면 그대로). 재수확 분도 같은 식 |
| 판매 단가 | M2 단가 × `(1 + 0.03 × market-sense)` |
| 부재 상한 | Caretaker 상한 + 2시간 × night-shift |
| 규칙 슬롯 | 컨트롤러가 있으면 레벨 × 2 + rule-memory, 없으면 0 |

## 5. 프레스티지

1. `/prestige`: Fertility가 0이면 오류(필요 100K, 지금 최고). 1 이상이면 선택지 상자 — 질문 `Lupin Bloom — start run #n?`, 설명 4줄(이번 판 최고·체크포인트 수·NEW BEST 수 / 얻을 Fertility / 초기화 / 유지), `Bloom and start over` · `Not yet`.
2. 고르면 `Are you sure? This cannot be undone.`(기본 No). 구매 확인 설정과 상관없다.
3. 실행(`App.DoPrestige` → `Prestige.Bloom`): 동기화 → 판 기록에 끝 날짜·Fertility → Fertility 더하기 → `NewRun(판 + 1, 새 난수, 보너스)` → 규칙 문장·켜짐/꺼짐 옮기기(실행 횟수·오류 지움) → 새 판 기록 → 업적 `first-bloom` → `● Lupin Bloom(run #n)` 이벤트(얻은 Fertility, 새 농장, 남은 규칙 수).
4. 장면: 농장 영역 모든 칸에 프레임 0~3을 0.7초씩. 장면 중에는 키·마우스를 버린다(보스키는 따로 동작). 2.8초 뒤 3의 이벤트들을 로그에 남긴다. 접힌 화면이면 장면 없이 바로 남긴다.

### 6.2 화면

- 선택지 상자가 로그 영역보다 크면 위로 올라가 농장 영역을 덮는다(헤더는 남긴다). 120×30에서 프레스티지 상자(14줄)가 잘리지 않는다.
- 자동완성: `/help ` 후보는 명령 다음에 장비 이름(`sickle  sickle · tool`, 창고는 이름만, K24). `/buy seed` 작물 후보 끝에 `plant now · 4d left` 또는 `Summer/Fall in 4d`. `/perks buy` 후보는 `Rich Soil Lv3 · 3 Fertility · growth +15%`, 최대면 `max`.
- 농장 그림(K23): 스프링클러 칸 오른쪽 아래(도트 5열, 글자 줄 3번째)에 레벨 숫자. 범위 영역 = 물 받는 칸(`Farming.Covered`) + 스프링클러 칸. 영역은 칸 흙(7×7)에 이웃한 영역 칸 사이 풀 줄(오른쪽 열·아래 줄, 네 칸이 모두 영역이면 모서리)까지 더한 도트 모양이고, 그 모양 안에서 상하좌우 중 하나가 밖인 도트를 물빛 `Q`(#6FC3F7)로 칠한다. 작물·스프링클러 그림 위에 긋는다. 장면 중에는 그리지 않는다.
- 부재 중 요약: 첫 줄 다음에 `checkpoint Day 28: 310K · best 280K (run #2) · ▲ 30.0K NEW BEST`.
