# 03. 시스템 설계

작성일: 2026-11-26 · 기준 문서: `wall-geop-lupin 기획·설계서.md`

Lupin Farm은 **개인 PC에서만 쓰는** 콘솔 게임이다. 서버, 계정, 네트워크 통신 없이 로컬에서만 동작한다. Windows Terminal의 PowerShell 탭 안에서 실행된다.

## 1. 구성도

```
 Windows Terminal ─ PowerShell 탭
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ lupin.exe (콘솔 앱, 대체 화면 버퍼)                                          │
 │                                                                          │
 │  InputReader ──키·마우스·크기──▶ App (UI 상태 기계) ──명령──▶ Commands        │
 │  (ReadConsoleInput)              │   ▲                       │            │
 │                                  │   │ LogEntry              ▼            │
 │  BossKey ──WM_HOTKEY──▶ App      │   └──────────────── Engine (틱 진행)    │
 │  (전역 단축키 스레드)              │                         │  ▲          │
 │                                  ▼                         ▼  │          │
 │                     Views (Header, Farm, Log,          GameState ◀── Content │
 │                     InputBox, Completion, Prompt)       Profile        (데이터) │
 │                                  │                         │              │
 │                     ScreenBuffer (셀 버퍼, 차분)          SaveStore          │
 │                                  │                   (save.json,          │
 │                     Terminal (VT 출력) ──────▶ 화면     profile.json)       │
 └──────────────────────────────────────────────────────────────────────────┘
```

## 2. 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 언어 | C# 5 | Windows 내장 컴파일러가 지원하는 최신 문법 |
| 런타임 | .NET Framework 4.8 (이 PC: 4.8.1) | Windows 기본. 설치 불필요 |
| 컴파일러 | `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe` | 개발 도구 설치 불필요. `merry-christmas`와 같은 방식 |
| 실행 형태 | 콘솔 exe (`/target:exe`) | PowerShell 탭 안에서 돈다 |
| 화면 출력 | VT 제어 문자 + 반쪽 블록 + 24비트 색 | `../0.reference/기술 스택 조사.md` 4절 |
| 입력 | Win32 `ReadConsoleInputW` (P/Invoke) | 키, 마우스, 창 크기 이벤트를 한 곳에서 받는다 |
| 전역 단축키 | Win32 `RegisterHotKey` + 메시지 루프 스레드 | 터미널에 포커스가 없어도 보스키 동작 |
| 저장 | JSON (`System.Web.Extensions`의 `JavaScriptSerializer`) | .NET Framework 기본 포함. 사람이 읽을 수 있다 |
| 테스트 | 직접 만든 작은 테스트 실행기 (`tests.exe`) | 외부 테스트 프레임워크 없이 같은 컴파일러로 빌드 |

### 3.1 의존 방향

```
Program ──▶ Ui ──▶ Core ──▶ Data(Content, Sprites)
   │         │
   │         └──▶ Data(Strings)
   └──▶ Storage ──▶ Core
```

- `Core`는 `Ui`, `Storage`, `System.Console`, `System.IO`, `DateTime.Now`를 쓰지 않는다. 현재 시각은 인자로 받는다.
- `Strings`(화면 문구)는 `Ui`만 쓴다. `Core`는 문구 키만 만든다.
- `tests.exe`는 `Core`와 `Data`만 묶어 빌드한다.

## 5. 실행 흐름

### 5.1 시작

1. 콘솔 모드를 저장하고 바꾼다 (5.4).
2. `profile.json`, `save.json`을 읽는다. 실패하면 `.bak`, 그래도 실패하면 새로 만든다.
3. 꺼져 있던 시간을 계산한다: `min(지금 UTC − savedAtUtc, 상한)` → 게임 분으로 바꿔 `Engine.CatchUp`(자동화만). 결과를 시작 환영 상자로 만든다.
4. 원래 탭 제목을 기억하고 `Windows PowerShell`로 바꾼다.
5. 화면을 지우고 `PS <현재 폴더>> ` 한 줄을 찍는다. 이 위치를 기억한다.
6. 대체 화면 버퍼로 들어간다.
7. 보스키 스레드를 시작한다.

### 5.2 메인 루프

```
loop:
  events = InputReader.Poll(30ms)        # WaitForSingleObject(입력 핸들, 30ms)
  App 이벤트 처리 (키, 마우스, 크기)
  보스키 신호가 있으면 보스 모드 전환
  경과 = 지금 − 마지막 처리 시각
    5분 이하: Engine.Advance(경과 게임 분, offline=false)
    5분 초과: 꺼져 있던 시간과 같은 규칙으로 처리 (상한, 자동화만)
  실제 30초마다 자동 저장
  보스 모드가 아니면:
    바뀐 것이 있으면 바로, 없으면 1초마다 Render → ScreenBuffer.Flush
```

- 게임 분은 실제 경과를 누적해 정수 부분만 쓴다. 나머지는 다음 루프로 넘긴다.
- 틱은 게임 10분 단위다. 하루 시작(06:00) 이벤트, 규칙 검사 주기, 체크포인트는 틱 경계에서 처리한다.
- M3 구현: `Engine.Advance`는 하루 시작과 규칙 검사 시각에서 구간을 나눠 성장 → 시세 → 스프링클러 → 계절 → 규칙 순서로 처리한다. 규칙 결과가 바뀔 일이 없으면 다음 다 자람 뒤의 검사까지 건너뛴다 (`../3.specification/M3_자동화 개발 명세.md` 5장).
- M4 구현: 엔진·규칙·명령은 기록을 `GameState`에만 쌓고(판 최고, 체크포인트, 판매 수입, 수확 수), 화면이 시작·진행 뒤·명령 앞뒤에 `Records.Sync`로 프로필에 옮긴다. 실제 날짜는 화면이 넘긴다 (`../3.specification/M4_기록·프레스티지 개발 명세.md` 4장).

### 5.3 종료

`Ctrl+C` 두 번, `/exit`, 예외 모두 같은 정리 순서를 따른다.

1. 저장한다.
2. 보스키를 해제한다.
3. 대체 화면 버퍼에서 나온다 (보스 모드였다면 이미 나와 있다).
4. 가짜 프롬프트 줄을 지운다 (`ESC[2K` + 줄 처음으로).
5. 탭 제목과 콘솔 모드를 되돌린다.
6. 예외였다면 `%LOCALAPPDATA%\LupinFarm\error.log`에 남기고 한 줄 안내를 출력한다.

`Main`은 `try/finally`로 감싸고, `AppDomain.UnhandledException`에서도 3~5를 실행한다. 터미널이 대체 화면에 갇히지 않게 하기 위해서다.

## 6. 화면 출력

### 6.1 셀 버퍼와 차분

- 셀 = 글자(문자열, 서로게이트 쌍 대비), 글자색(RGB 또는 기본색), 배경색(RGB 또는 기본색).
- 한글 같은 2칸 문자는 첫 칸에 글자, 둘째 칸에 "이어짐" 표시를 둔다 (`TextWidth`).
- `Flush`는 이전 프레임과 다른 칸만 골라, 연속된 칸을 묶어 `ESC[줄;칸H` + 색 변경 + 글자로 출력한다. 한 프레임을 문자열 하나로 모아 한 번에 쓴다.
- 창 크기가 바뀌면 이전 프레임을 버리고 전체를 다시 그린다.

### 6.2 농장 도트

- 칸 하나 = 스프라이트 8×8 → 글자 8칸 × 4줄. 글자 한 칸은 `▀` + 글자색(위 픽셀) + 배경색(아래 픽셀).
- 위아래 픽셀 색이 같으면 공백 + 배경색으로 출력해 양을 줄인다.
- 밤에는 팔레트 색에 0.55를 곱하고, 계절에 따라 풀 색을 바꾼다.

### 6.3 커서

- 실제 터미널 커서를 입력창 글자 위치에 두고 보이게 한다 (작업 화면처럼 보이도록).
- 선택지·장면 중에는 커서를 숨긴다.

## 7. 입력

| 이벤트 | 처리 |
| --- | --- |
| 키 | 가상 키 코드 + 유니코드 글자 + 수정키(Ctrl, Alt, Shift). `App`이 상태(보통, 선택지, 장면, 보스)에 따라 분배 |
| 마우스 클릭 | 화면 좌표 → `Layout`의 영역 판정 → `◀` `▶`, 페이지 점, 밭 칸 |
| 마우스 휠 | 로그 영역이면 로그 스크롤 |
| 창 크기 | `Layout` 다시 계산, 전체 다시 그리기 |

**확인 필요**: Windows Terminal이 `ENABLE_MOUSE_INPUT`을 켠 콘솔 앱에 마우스 이벤트를 전달하는지 M1에서 확인한다. 안 되면 VT 마우스 모드(`ESC[?1000h`, `ESC[?1006h`)를 켜고 키 이벤트로 들어오는 VT 문자열을 해석하는 방식으로 바꾼다. 둘 다 안 되면 명령어와 `PgUp`/`PgDn`만 쓴다.

## 8. 보스키

- 별도 스레드에서 `RegisterHotKey(IntPtr.Zero, id, 수정키 | MOD_NOREPEAT, 키)`를 등록하고 `GetMessage` 루프를 돈다.
- `WM_HOTKEY`를 받으면 메인 루프가 읽는 플래그를 세운다 (`Interlocked`).
- 보스 모드 진입: 대체 화면에서 나온다 → 가짜 프롬프트 뒤 커서가 보인다. 이후 화면 출력을 멈춘다.
- 보스 모드 해제: 대체 화면으로 돌아가 전체를 다시 그린다.
- 조합 변경(`/config bosskey`)은 스레드에 메시지를 보내 해제 후 다시 등록한다.

## 9. 시간 처리

| 상황 | 기준 시계 | 처리 |
| --- | --- | --- |
| 켜져 있는 동안 | `DateTime.UtcNow` 차이 | 루프마다 경과를 게임 분으로 바꿔 `Engine.Advance` |
| 루프 사이 5분 초과 (절전 등) | `DateTime.UtcNow` 차이 | 상한 적용, 자동화만 (`CatchUp`) |
| 꺼져 있던 시간 | 지금 UTC − `savedAtUtc` | 상한 적용, 자동화만 (`CatchUp`) |
| 시계가 뒤로 감 | | 경과 0 |
| 일별 기록 | `DateTime.Now`의 로컬 날짜 | 날짜가 바뀌면 새 항목 |

`Core`에는 "지금 UTC"와 "오늘 로컬 날짜"를 인자로 넘긴다.

## 10. 저장

| 파일 | 위치 | 내용 |
| --- | --- | --- |
| `save.json` | `%LOCALAPPDATA%\LupinFarm\` | 현재 판 (02 4절) |

## 11. 빌드와 테스트

| 명령 | 내용 |
| --- | --- |
| `build.bat` | `csc /target:exe /optimize+ /codepage:65001 /r:System.Web.Extensions.dll /recurse:src\*.cs /out:bin\lupin.exe` |
| `build.bat test` | `src\Core`, `src\Data`, `tests`를 묶어 `bin\tests.exe`로 빌드하고 실행. 실패가 있으면 종료 코드 1 |
