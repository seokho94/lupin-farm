# 02. 도메인 모델 및 데이터 포맷

작성일: 2026-11-26 · 기준 문서: `wall-geop-lupin 기획·설계서.md`

콘텐츠 데이터의 원본은 `src/Data/Content.cs`가 된다. 아래 수치는 M5 밸런스 조정(2026-11-27, `bin\tests.exe balance` 시뮬레이션) 뒤의 값이다. 조정 전 값과 이유는 `../3.specification/M5_편의·밸런스 개발 명세.md` 4장. 데이터를 고치면 이 문서도 맞추고, `tests.exe balance`로 진행 속도를 다시 본다.

## 1. 도메인 모델

```
Profile (profile.json) ─┬─ settings          언어, 배속, 구매 확인, 보스키
  판을 넘어 남는 것       ├─ fertility, perks   Fertility 잔액, 영구 보너스 레벨
                         ├─ runs [RunRecord]   판별 기록 (현재 판 포함)
                         ├─ daily [DailyRecord] 실제 날짜별 기록
                         ├─ dex, achievements  도감, 업적
                         └─ history            이전 명령 100개

Save (save.json) ───────┬─ run, gameMinute     판 번호, 게임 시계
  현재 판                ├─ gold, invested      골드, 투자액
                         ├─ tools, storage, seeds, unlocked, equipmentBox
                         ├─ fields [Field] ──── plots [Plot] (30칸)
                         ├─ farm                농장 전체 장비 (출하함, 자동 구매기, 컨트롤러, Caretaker)
                         ├─ market {작물: MarketState}, rng
                         └─ rules [Rule]
```

| 개념 | 설명 |
| --- | --- |
| Run (판) | 프레스티지와 프레스티지 사이의 농장 하나. 번호는 1부터 |
| Field (구역) | 밭 10칸 × 3줄. 화면의 한 페이지 |
| Plot (칸) | 잠김 / 빈 칸 / 작물 / 스프링클러 중 하나 |
| Crop (작물) | 콘텐츠 정의. 계절, 해금 비용, 씨앗값, 기준가, 성장 기간, 재수확 기간 |
| Tool (농기구) | 물뿌리개(`can`), 씨앗 주머니(`bag`), 낫(`sickle`). 레벨이 명령 범위를 정한다 |
| Equipment (장비) | 자동화 장비 8종 |
| Rule (규칙) | `when <조건> do <행동>` 문장 하나 |
| Net worth (총자산) | 점수. 골드 + 창고·씨앗 평가액 + 투자액 |

## 2. 시간

| 항목 | 정의 |
| --- | --- |
| 기본 단위 | 정수 게임 분 (`gameMinute`). 0 = Day 1 봄 1일 06:00 |
| 날짜 | `day = gameMinute / 1440 + 1` (하루는 06:00에 바뀐다) |
| 시각 | `(360 + gameMinute % 1440) % 1440` 분 → `hh:mm` |
| 밤 | 시각 22:00~06:00 |
| 계절 | `season = ((day - 1) / 7) % 4` (0 봄, 1 여름, 2 가을, 3 겨울), `seasonDay = (day - 1) % 7 + 1` |
| 배속 | `timescale` = 게임 1시간에 해당하는 실제 초. 기본 60, 범위 5~600 |
| 틱 | 게임 10분. 엔진은 틱 단위로 진행한다 |
| 하루 시작 이벤트 | `gameMinute % 1440 == 0`: 끝난 날의 판 최고·체크포인트(시세 갱신 전), 시세 갱신, 스프링클러 물 주기, 계절, 규칙 (M3 K5, M4 K3) |

### 2.1 꺼져 있던 시간의 상한

| Caretaker 레벨 | 상한 (실제 시간) | 비용 |
| --- | --- | --- |
| 0 | 2시간 | 기본 |

## 3. 콘텐츠 (`Content.cs`)

### 3.1 시작 상태

| 항목 | 값 |
| --- | --- |
| 골드 | 100G (+ Head Start 보너스) |
| 열린 밭 | 구역 1 `A1`~`A6` (+ Old Fields 보너스) |

### 3.2 작물

| ID | 이름 (ko) | 계절 | 해금 | 씨앗 | 기준가 | 성장 | 재수확 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `turnip` | 순무 | 봄 | 0 | 10G | 45G | 2일 | - |
| `potato` | 감자 | 봄 | 200G | 25G | 120G | 4일 | - |
| `strawberry` | 딸기 | 봄 | 1,500G | 40G | 75G | 3일 | 1일 |
| `corn` | 옥수수 | 여름·가을 | 0 | 60G | 225G | 7일 | - |
| `tomato` | 토마토 | 여름 | 600G | 30G | 120G | 3일 | 2일 |
| `melon` | 멜론 | 여름 | 4,000G | 150G | 750G | 10일 | - |
| `carrot` | 당근 | 가을 | 0 | 20G | 75G | 3일 | - |
| `eggplant` | 가지 | 가을 | 900G | 30G | 80G | 2일 | 2일 |
| `pumpkin` | 호박 | 가을 | 5,000G | 100G | 630G | 10일 | - |
| `mushroom` | 버섯 | 겨울 | 300G | 30G | 105G | 3일 | - |

- 성장 기간은 물이 있는 시간만 센다. 영구 보너스 Rich Soil이 성장 속도를 높인다.
- 재수확은 제철에만 되고 계절은 7일이라(D5), 재수확 작물은 계절 첫날 심으면 그 계절 안에 여러 번 거두도록 성장·재수확 일수를 짧게 둔다: 딸기 4번(4·5·6·7일차), 토마토 2번(4·6일차), 가지 3번(3·5·7일차). M5 전에는 첫 수확이 계절 끝이라 재수확이 없어 손해였다 (M5 이슈 1).
- 하루당 이익(기준가, 계절 첫날 심음): 봄 순무 17.5 < 감자 23.8 < 딸기 37, 여름 옥수수 23.6 < 토마토 30 < 멜론 60, 가을 당근 18.3 < 옥수수 23.6 < 가지 30 < 호박 53, 겨울 버섯 25. 해금 비용이 높을수록 이익이 크다.
- 단계 경계: 씨앗 0%, 새싹 25%, 자라는 중 60%, 다 자람 100%.
- 겨울은 일부러 작물이 적다 (온실 동기).

### 3.3 농기구

| 농기구 | 명령 | Lv1 | Lv2 (200G, M1 K3) | Lv3 (5,000G) |
| --- | --- | --- | --- | --- |
| 물뿌리개 `can` | `/water` | 한 칸 | 한 줄 안의 범위 | 구역 안의 모든 범위 |
| 씨앗 주머니 `bag` | `/plant` | 한 칸 | 한 줄 안의 범위 | 구역 안의 모든 범위 |
| 낫 `sickle` | `/harvest` | 한 칸 | 한 줄 안의 범위 | 구역 안의 모든 범위 |

`/harvest ready`는 다 자란 칸 중 낫 레벨이 허용하는 만큼 수확한다: Lv1은 첫 1칸, Lv2는 다 자란 칸이 있는 첫 줄, Lv3는 구역 전체.

### 3.4 땅과 창고

| 항목 | 비용 |
| --- | --- |
| 구역 n의 다음 칸 | `50 × 2^(n - 1) × 1.06^(그 구역에서 산 칸 수)` (시작 칸 제외). 예: 구역 1에서 14칸을 샀으면 113G, 구역 2의 첫 칸 100G |
| 새 구역 n (n ≥ 2) | `8,000 × 2.5^(n - 2)`: 구역 2 8,000G, 구역 3 20,000G, 구역 4 50,000G |
| 창고 용량 | Lv0 40, 레벨마다 2배. 비용 `400 × 3^(현재 레벨)`. 최대 Lv20 (M2 K6) |

### 3.5 장비

| ID | 장비 | 단위 | 비용 | 효과 |
| --- | --- | --- | --- | --- |
| `sprinkler` | 스프링클러 | 칸 | 300G (Lv2 업그레이드 2,000G, Lv3 10,000G) | 설치할 때와 매일 06:00에 범위에 물. Lv1 상하좌우 4칸, Lv2 주변 8칸, Lv3 5×5 (구역이 3줄이라 최대 14칸) |
| `harvester` | 자동 수확기 | 구역 | 1,500G | 규칙 `harvest` |
| `planter` | 자동 파종기 | 구역 | 5,000G | 규칙 `plant` |
| `greenhouse` | 온실 | 구역 | 50,000G | 계절 제한 없음 |
| `shipping-bin` | 출하함 | 농장 | 1,000G | 규칙 `sell` |
| `auto-buyer` | 자동 구매기 | 농장 | 4,000G | 규칙 `buy` |
| `controller` | 농장 컨트롤러 | 농장 | Lv1 1,000G, Lv2 8,000G, Lv3 40,000G, 이후 레벨마다 ×5, 최대 Lv20 | 슬롯 = 레벨 × 2. 검사 주기(게임 시간) Lv1 60분 / Lv2 30분 / Lv3 이상 10분 |
| `caretaker` | Caretaker | 농장 | 2.1절 | 꺼져 있던 시간 상한 |

스프링클러는 산 뒤 장비 보관함에 들어가고 `/place`로 설치한다. 물은 같은 구역의 열린 칸에만, `물 끝 = max(지금 끝, 지금 + 24시간)`으로 준다. 컨트롤러·Caretaker는 `/buy`가 Lv1을 사고 이후 `/upgrade`로 올린다. 규칙은 최대 30개 (M3 K1~K3, K15).

### 3.6 시세

| 상수 | 값 | 설명 |
| --- | --- | --- |
| 초기 계수 | 1.0 | 시세 = 기준가 × 계수 × 제철 배수 × 보너스 |
| 매일 변동 | `f ← f + 0.3 × (1 - f) + N(0, 0.08)` | 기준가로 돌아오는 무작위 변동 |
| 계수 범위 | 0.5 ~ 2.0 | |
| 판매 압력 | 1개 팔 때마다 `f ← f × 0.998` | 100개면 약 0.82배 |
| 제철 아님 | × 1.3 | |
| 단가 | `max(1, round(시세))` | 한 번에 여러 개를 팔면 1개마다 계수를 내리며 합산한다 (등비수열 합으로 한 번에 계산, 합계만 반올림. M2 K1) |
| 하한 뒤 판매 | 계수 0.5 고정 | 0.5에 닿은 뒤 파는 것은 0.5 기준 (M2 K2) |

### 3.7 기록과 프레스티지

| 항목 | 값 |
| --- | --- |
| 체크포인트 | Day 7 × 2^k (7, 14, 28, 56, 112, 224, …). Day d가 끝나는 순간(Day d+1 06:00, 시세 갱신 전)의 총자산 (M4 K3) |
| Fertility | `floor(sqrt(이번 판 최고 총자산 / 100,000))` |
| 일별 기록 | 실제 날짜(로컬)별. 보관 기간 제한 없음 |

| 영구 보너스 ID | 이름 | 레벨당 효과 | 최대 |
| --- | --- | --- | --- |
| `rich-soil` | Rich Soil | 성장 속도 +5% | 없음 |
| `market-sense` | Market Sense | 판매 가격 +3% | 없음 |
| `head-start` | Head Start | 시작 골드 +500G | 없음 |
| `old-fields` | Old Fields | 시작 열린 칸 +2 | 12 (24칸) |
| `night-shift` | Night Shift | 꺼져 있던 시간 상한 +2시간 | 없음 |
| `rule-memory` | Rule Memory | 규칙 슬롯 +1 | 4 |
| `seasoned-hands` | Seasoned Hands | 농기구 시작 레벨 +1 | 2 |

다음 레벨 비용 = 현재 레벨 + 1 Fertility.

M4 구현 (K13): Rich Soil은 심을 때 칸의 필요 성장 분을 `올림(성장 분 / (1 + 0.05 × 레벨))`로 정한다(이후 심는 작물부터, 재수확 분도 같은 식). Market Sense는 단가에 `1 + 0.03 × 레벨`을 곱한다. Rule Memory는 컨트롤러가 있을 때만 슬롯에 더한다. Head Start·Old Fields(구역 1)·Seasoned Hands는 새 판을 만들 때 붙는다.

## 4. 세이브 (`save.json`)

```json
{
  "version": 1,
  "run": 3,
  "savedAtUtc": "2026-11-26T05:08:00Z",
  "gameMinute": 43800,
  "gold": 1240.0,
  "invested": 5300.0,
  "rng": 2463534242,
  "tools": { "can": 2, "bag": 1, "sickle": 2 },
  "storageLevel": 0,
  "storage": { "turnip": 28 },
  "seeds": { "turnip": 12, "corn": 30 },
  "unlocked": ["turnip", "corn", "carrot", "potato"],
  "equipmentBox": { "sprinkler1": 1 },
  "fields": [
    {
      "open": 20,
      "harvester": true, "planter": false, "greenhouse": false,
      "plots": [
        { "crop": "turnip", "growth": 2880, "waterUntil": 44100, "harvests": 0 },
        { "sprinkler": 1 },
        {}
      ]
    }
  ],
  "farm": { "shippingBin": true, "autoBuyer": false, "controller": 2, "caretaker": 0 },
  "market": { "turnip": { "f": 1.04, "yesterday": 1.01 } },
  "rules": [ { "text": "when f2 ready do harvest", "on": true, "runs": 12 } ],
  "peakNetWorth": 310000.0,
  "peakDay": 31
}
```

| 필드 | 설명 |
| --- | --- |
| `gameMinute` | 이번 판의 게임 시계 |
| `savedAtUtc` | 저장한 실제 시각(UTC). 꺼져 있던 시간 계산에 쓴다 |
| `invested` | 땅, 농기구, 장비, 작물 해금에 쓴 골드 합계 |
| `rng` | 시세 난수 상태 (xorshift32) |
| `plots[i]` | 인덱스 = 줄 × 10 + 칸 (A1 = 0, C10 = 29). `i >= open`이면 잠김. `{}`는 빈 칸 |
| `plot.growth` | 물이 있는 동안 쌓인 성장 게임 분 |
| `plot.waterUntil` | 이 게임 분까지 물이 있다 |
| `plot.harvests` | 재수확 작물의 수확 횟수 (0이면 첫 성장 중) |
| `plot.sprinkler` | 설치된 스프링클러 레벨 |
| `equipmentBox` | 설치하지 않은 스프링클러 (`sprinkler1` = Lv1 개수) |

`version`이 오르면 불러올 때 이전 형식을 변환한다.

실제 저장 키는 `JavaScriptSerializer`가 쓰는 PascalCase(`GameMinute`, `EquipmentBox`, `Farm.Controller`, `Rules[].Text` …)다. M3에서 정한 장비·규칙 필드는 `../3.specification/M3_자동화 개발 명세.md` 3장, M4의 기록 필드(`PeakNetWorth`, `Checkpoints`, `Earned`, `Harvested`, `Perks` 사본, 칸의 `Need`)는 `../3.specification/M4_기록·프레스티지 개발 명세.md` 3장.

```json
}
```

- 현재 판 기록(`endedAt: null`)도 `runs`에 두고 계속 갱신한다. 세이브가 깨져도 기록이 남는다.
- M4 구현: 실제 키는 PascalCase(`Fertility`, `Perks`, `Runs[].Checkpoints`, `Daily[].EarnedBase`, `Dex.turnip.Total`, `Achievements`). 판 기록에는 도감에 옮긴 이번 판 수확 수(`Harvested`)도 둔다. 일별 기록은 판마다 따로이고, 번 돈 = 판의 판매 합계 − 그날 처음 기록할 때의 합계(`EarnedBase`)다.
- 예시의 Fertility: 판 1에서 9, 판 2에서 3을 얻어 12, 영구 보너스에 4(rich-soil Lv2 = 1 + 2, night-shift Lv1 = 1)를 써서 8이 남았다.
- 날짜는 로컬 날짜 `yyyy-MM-dd`다.

### 5.1 내보내기 파일 (`/save export`, M5 K6~K8)

판과 프로필을 파일 하나로 묶는다. 기본 위치는 저장 폴더의 `export\lupin-yyyyMMdd-HHmmss.json`, 가져오기 직전의 자동 백업은 `export\before-import-yyyyMMdd-HHmmss.json`이다. `/reset`은 `export` 폴더를 지우지 않는다.

```json
{
  "Format": "lupin-farm-export",
  "Version": 1,
  "ExportedAt": "2026-11-27T07:10:02.0000000Z",
  "Save": { "Version": 1, "Run": 1, "GameMinute": 135700, "Gold": 3070, "...": "save.json과 같음" },
  "Profile": { "Version": 1, "CurrentRun": 1, "Settings": { "Lang": "en", "...": "" }, "...": "profile.json과 같음" }
}
```

- `Format`이 다르면 "내보내기 파일이 아님", `Version`이 이 게임보다 높으면 "새 버전 파일", 읽지 못하거나 `Save`·`Profile`이 없으면 "깨진 파일"로 거부한다. 지금 데이터는 그대로다.
- 가져온 판·프로필은 `Normalize()`를 거친다(이전 버전 파일 호환). 내보낸 시각(`Save.SavedAtUtc`)부터 지난 실제 시간은 꺼져 있던 시간으로 반영한다(상한 적용).

## 6. 문법

### 6.1 밭 범위

```
target  := [ field "." ] range
field   := "f" 숫자                      예: f2
range   := cell | cell ":" cell | row | "all"
cell    := row col                       예: A1, C10
row     := "A" | "B" | "C"
col     := 1 ~ 10
```

`A1:C3`은 A1과 C3을 꼭짓점으로 하는 사각형(9칸)이다. 대소문자를 구분하지 않는다.

### 6.2 규칙

```
rule    := "when" cond "do" action
cond    := fieldRef ("ready" | "empty")
         | "price" crop op number
         | ("stock" | "seed") crop op number
fieldRef:= "f" 숫자 | "all"
op      := ">=" | "<=" | ">" | "<" | "="
action  := "harvest" [fieldRef]
         | "plant" crop [fieldRef]
         | "sell" crop [number] | "sell" "all"
         | "buy" "seed" crop number
```

M3 구현 (K6): `stock`은 `stock all`(창고 전체 개수)도 받는다. `sell all` 뒤에는 개수를 쓰지 않는다. 비교 연산자는 붙여 써도 된다(`turnip>=35`). 저장은 소문자·공백 하나로 정리한 문장이다.

- `ready`: 그 구역에 다 자란 칸이 하나 이상. `empty`: 빈 칸이 하나 이상.
- `harvest`, `plant`는 구역 전체에 적용한다. 구역을 생략하면 조건의 구역이다 (조건이 시세·재고면 생략할 수 없다).

## 7. 로그 이벤트

게임 로직은 화면 문구 대신 로그 이벤트를 돌려준다.

```
LogEntry { kind, title: Msg, lines: [Msg] }
Msg      { key, args[] }        예: { "harvest.title", ["field 1"] }
kind     Input | Ok | Error | Auto | Event | Info
```

| kind | 표시 |
| --- | --- |
| `Input` | 회색 `>` + 입력한 명령 |
| `Ok` | 초록 `●` |
| `Error` | 빨강 `●` |
| `Auto` | 주황 `●` (규칙 실행) |
| `Event` | 노랑 `●` (계절, 체크포인트, 업적) |
| `Info` | 기본색 `●` (도움말, 표) |

## 8. 문자열 표 (`Strings.cs`)

- 키 규칙: `<영역>.<이름>`. 예: `harvest.title`, `harvest.done`, `err.no_gold`, `crop.turnip`, `ui.hint`.
- 값은 `string.Format` 형식 (`"{0} x{1} → storage {2}/{3}"`).
- `en`, `ko` 두 표의 키 집합이 같아야 한다 (테스트로 검사).

## 9. 숫자 표기

| 범위 | 표기 | 예 |
| --- | --- | --- |
| 10,000 미만 | 천 단위 쉼표 | `1,240` |
| 10,000 이상 | 유효 숫자 3자리 + 단위 | `12.4K`, `3.40M`, `5.60B`, `7.80T` |
| 단위 | K, M, B, T, Qa, Qi, Sx, Sp, Oc, No, Dc | |
| Dc 이상 | 지수 표기 | `1.2e36` |

골드와 수량은 `double`로 다룬다 (`long`은 약 9.2×10^18에서 넘친다).

골드는 10,000 미만이면 `1,240G`, 줄여 쓰면 단위 사이를 띄워 `200K G`로 적는다 (M2 이슈 2: `200KG`가 킬로그램처럼 읽힘). 띄우는 글자는 줄바꿈하지 않는 공백(U+00A0)이라 로그 낱말 줄바꿈에서 `200K`와 `G`가 갈라지지 않는다 (M5 이슈 8).
