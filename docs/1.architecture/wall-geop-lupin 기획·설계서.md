## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 이름 | Lupin Farm |
| 형태 | Windows Terminal의 PowerShell 탭에서 실행하는 콘솔 게임. 설치 없는 단일 exe (C# 5, .NET Framework 4.8 내장 컴파일러) |
| 사용자 | 본인 1명, 회사 PC, 로컬 전용 |
| 컨셉 | Claude Code 같은 화면에서 영어 슬래시 명령어로 농사짓고, 팔고, 투자하고, 농장을 자동화하는 농사 타이쿤 |

## 2. 목표와 차별점

- **업무 화면처럼 보이는 게임**: 화면이 AI 코딩 도구 작업 세션처럼 보이고, 조작은 타이핑이다. `/hide`로 농장을 접고, 보스키로 평범한 PowerShell 프롬프트만 남긴다.
- **명령어가 곧 조작, 농기구가 곧 범위**: 농기구를 업그레이드하면 명령 한 줄로 처리하는 범위가 넓어진다 (한 칸 → 한 줄 → 구역 전체).
- **자동화를 직접 짠다**: 장비가 기능을 열고, `when … do …` 규칙으로 조합한다. 다른 농장 게임과 다른 점이다.
- **손해 없는 방치**: 작물은 시들지 않고 성장만 멈춘다. 계절은 새로 심는 것만 제한한다. 꺼져 있던 시간은 상한까지만 반영한다.
- **기록을 깨는 무한 성장**: 엔딩 대신 총자산 체크포인트, 일별 기록, 랭킹, 프레스티지(Lupin Bloom)로 지난 판을 넘어서는 것이 목표다.
- **오리지널**: 동물의 숲·스타듀 밸리는 장르와 메커니즘만, Claude Code는 화면 배치와 분위기만 참고한다.

## 3. MVP 범위

### 3.1 포함 (M1~M4)

- 화면: 헤더, 도트 농장 영역(고정 14줄), 로그, 둥근 테두리 입력창, 안내 줄. 시작 환영 상자, 자동완성 목록, 번호 선택지
- 입력: 한 줄 편집, 이전 명령, `Tab` 자동완성, 마우스(페이지 버튼, 밭 클릭, 로그 휠)
- 시간: 실제 시간 배속(기본 실제 60초 = 게임 1시간), 계절 7일, 밤 표시, 꺼져 있던 시간 상한 반영
- 농사: 작물 10종(해금 포함), 심기·물 주기·수확·뽑기, 재수확 작물
- 땅: 구역(10칸 × 3줄) 확장, 페이지 전환(명령, `PgUp`/`PgDn`, `◀` `▶` 클릭)
- 경제: 상점, 농기구 3종 Lv1~3, 창고 용량, 시세(매일 변동, 판매 압력, 제철)
- 자동화: 장비 8종(스프링클러, 자동 수확기, 자동 파종기, 출하함, 자동 구매기, 온실, 농장 컨트롤러, Caretaker), 규칙(`/auto`)
- 기록: 총자산, 체크포인트·일별·최고 기록, 랭킹, 도감, 업적
- 프레스티지: Lupin Bloom, Fertility, 영구 보너스 7종
- 위장: 시작 시 가짜 프롬프트, 보스키, `/hide`
- 설정: 언어(영어 기본, 한국어), 배속, 구매 확인, 보스키 조합. 자동 저장

## 4. 설계 원칙

### 4.1 들키지 않기 위한 조건

| 번호 | 조건 | Lupin Farm에서 |
| --- | --- | --- |
| P1 | 소리·큰 움직임 없음 | 무음. 움직이는 것은 1초 주기 스피너와 작물 단계 변화 정도 |
| P2 | 언제든 멈춤 | 시들지 않음, 다 자란 작물은 기다림, 명령어 한 줄짜리 조작 |
| P3 | 업무 화면처럼 보임 | AI 코딩 도구 세션 같은 화면, 영어 로그, `/hide` |
| P4 | 보스키 | 전역 단축키로 평범한 PowerShell 프롬프트 화면 |

### 4.2 구현 원칙

- 게임 로직(`src/Core`)은 콘솔, 파일, 현재 시각을 직접 쓰지 않는다. 시간은 인자로 받는다. 그래서 `tests.exe`로 시뮬레이션 테스트를 할 수 있다.
- 게임 로직은 화면 문구를 만들지 않는다. "문구 키 + 값"으로 된 로그 이벤트를 돌려주고, 화면이 문자열 표로 바꾼다.
- 밸런스와 콘텐츠는 `src/Data/Content.cs` 한 곳에서 고친다.
- 화면 문구는 `src/Data/Strings.cs`의 문자열 표(영어, 한국어)에 둔다. 두 언어의 키가 같아야 한다.
- 외부 네트워크 요청을 하지 않는다.

## 5. 핵심 결정

| 결정 | 내용 | 근거 |
| --- | --- | --- |
| D1 | C# 5 + .NET Framework 4.8 내장 `csc.exe`로 콘솔 exe 하나를 만든다. 외부 라이브러리 없음 | 설치 권한 없는 회사 PC. `../0.reference/기술 스택 조사.md` 6절 |
| D2 | 시간의 기본 단위는 정수 **게임 분**이다. 게임 분 0 = Day 1 봄 06:00. 시뮬레이션은 게임 10분 단위로 진행한다 | 정수라서 계산과 테스트가 정확하다 |
| D3 | 배속은 "게임 1시간에 해당하는 실제 초"로 정한다. 기본 60초 | 사용자 결정 (실제 1분 = 게임 1시간) |
| D4 | 꺼져 있던 시간은 실제 시간 기준 상한까지만 반영하고, 그동안은 자동화만 일한다. 상한은 Caretaker와 Night Shift로 늘린다 | 사용자 결정. 하룻밤이 게임 37일이 되는 것을 막는다 |
| D5 | 방치 페널티 없음: 물이 없으면 성장만 멈추고, 다 자란 작물은 기다리며, 계절은 파종과 재수확만 제한한다 | P2 |
| D6 | 화면은 셀 버퍼(글자, 글자색, 배경색)에 그리고 이전 프레임과 비교해 바뀐 칸만 VT 제어 문자로 출력한다 | 깜빡임 방지, 적은 출력량 |
| D7 | 농장 영역은 고정 14줄, 밭 한 칸 8×8 픽셀(글자 8칸 × 4줄), 구역 하나 10칸 × 3줄 고정 | 1/3로는 도트가 부족하다. 창 크기에 따라 배치가 흐트러지지 않게 고정한다 |
| D8 | 입력은 `ReadConsoleInput`으로 키·마우스·창 크기 이벤트를 함께 읽는다 | 마우스 지원, 입력 중에도 화면 갱신 |
| D9 | 저장은 두 파일이다. `save.json`(현재 판)과 `profile.json`(기록, 보너스, 도감, 설정). 임시 파일에 쓴 뒤 바꿔치기하고 직전 버전을 `.bak`으로 남긴다 | 프레스티지나 세이브 손상에도 기록이 남는다. 강제 종료에 대비한다 |
| D10 | 시세 난수는 세이브에 저장한 상태로 만든다 | 같은 입력이면 같은 결과. 오프라인 계산과 테스트가 재현된다 |
| D11 | 점수 = 총자산 = 골드 + 창고 평가액 + 씨앗 평가액 + 투자액(땅, 농기구, 장비, 작물 해금) | 투자해도 점수가 떨어지지 않는다 |
| D12 | 명령어와 인자는 항상 영어이고, 화면 문구만 영어·한국어로 바꾼다 | 사용자 결정. 위장과 해석기 단순화 |
| D13 | 규칙 행동은 장비가 열고, 규칙 문장은 프레스티지 후에도 남는다 | 사용자 결정(장비형 + 규칙형). 다시 시작할 때 편하다 |
| D14 | 명령어에 구역 접두사(`f2.`)가 없으면 지금 보고 있는 구역을 대상으로 한다. 규칙에서는 구역을 반드시 적는다 | 보는 구역이 바뀌어도 규칙 동작이 바뀌지 않는다 |
