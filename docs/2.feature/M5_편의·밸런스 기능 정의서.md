# M5_편의·밸런스 기능 정의서

작성일: 2026-11-27 · 기준 문서: `../1.architecture/wall-geop-lupin 기획·설계서.md`, `01_요구사항 정의서.md`, `02_도메인 모델 및 데이터 포맷.md`, `04_화면 설계.md`, `M4_기록·프레스티지 기능 정의서.md`

M5 구현 범위와 규칙이다. 설계 문서와 다른 점은 이 문서가 우선하며, 구현 후 개발 명세의 "정의서와 달라진 점"에 남긴다.

## 1. 목표와 범위

M1~M4를 해 보며 불편했던 곳을 고치고 진행 속도를 맞춘다. 범위는 기획서 6장의 M5 후보 중 사용자가 고른 4개와, M4 중에 제안한 개선 2개다 (사용자 결정 2026-11-27).

| 포함 | 요구사항 |
| --- | --- |
| 한글 자판 상태에서 친 명령을 영문 키로 바꿔 넣기 | FR-CMD-11 |
| 넓은 창에서 구역 2개 나란히 보기 | FR-UI-12 |
| 로그 낱말 단위 줄바꿈 | FR-UI-13 |
| 로그 한 줄 안에서 글자색 나누기 (▲ 초록, ▼ 빨강 등) | FR-UI-14 |
| 세이브 내보내기·가져오기 `/save` | FR-SET-10, 11 |
| 스프링클러 설치·업그레이드 범위 미리 보기 | FR-EQP-08 |
| 정보 칸에 보관함 스프링클러 수 | FR-EQP-09 |

| 밸런스 조정 (진행 속도 시뮬레이션과 수치 조정) | NFR-11 |

## 2. 확정한 결정

| 번호 | 결정 |
| --- | --- |
| K1 | 입력창에 들어오는 한글(호환 자모 `ㄱ`~`ㅣ`, 음절 `가`~`힣`)은 두벌식 자판에서 같은 자리의 영문 키로 바꿔 넣는다. 예: `/ㅔㅣ뭇 ㅅㅕ구ㅑㅔ` → `/plant turnip`. 음절은 초성·중성·종성으로 나누고, 겹모음·겹받침은 키 두 개(`ㅘ` → `hk`, `ㄳ` → `rt`), 된소리·`ㅒ`·`ㅖ`는 Shift 글자(`ㄲ` → `R`, `ㅖ` → `P`)다. 명령과 이름은 대소문자를 가리지 않으므로 그대로 동작한다. 명령어와 인자는 항상 영어라(D12) 한글을 넣을 곳이 없다. 예외: `/save export`·`/save import` 뒤의 파일 경로는 바꾸지 않는다(한글 폴더 이름) |
| K2 | 바꿔 넣은 글자가 있으면 입력창 위 테두리 오른쪽에 "한글 자판 → 영문 키로 바꿔 넣음 (한/영 키)"를 보여 준다(자동완성 목록이 안내 줄을 덮어도 보이게). 입력을 지우거나 실행하면 사라진다. 명령 실행(`Commands.Execute`)도 같은 변환을 거친다 |
| K3 | 창 폭이 204칸 이상이고 구역이 2개 이상이면 농장 영역에 구역 2개를 나란히 그린다 (높이 14줄 그대로). 보는 구역과 다음 구역을 그리고, 보는 구역이 마지막이면 이전 구역과 마지막 구역을 그린다. 명령의 기본 대상(D14)과 정보 칸은 보는 구역이다. 보는 구역은 줄 이름(A~C)과 아래 테두리의 구역 이름을 강조색으로 쓴다. 다른 구역의 칸을 클릭하면 `f2.B3`처럼 접두사를 붙여 넣는다. 페이지 점은 정보 칸 아래로 옮긴다 |
| K4 | 로그 줄이 화면 폭을 넘으면 낱말 사이(공백)에서 줄을 바꾼다. 한 낱말이 한 줄보다 길면 글자 단위로 자른다. 이어지는 줄은 지금처럼 들여쓴다. 시작 상자·선택지 상자처럼 줄바꿈하지 않는 줄은 그대로 |
| K5 | 코어는 값에 색의 뜻(`Tone`: 좋음, 나쁨, 주의, 흐림)을 붙이고, 화면이 그 부분만 초록·빨강·주황·회색으로 그린다. 문구 표(`Strings.cs`)는 바뀌지 않는다. 적용: `/market` 오늘 변동(`▲` 초록, `▼` 빨강)과 기준가 대비(+ 초록, - 빨강), `/records` 차이(`▲` 초록, `▼` 빨강), `/growing` 다 자람(초록)·멈춤(주황), 체크포인트 `NEW BEST`(초록). 시작 상자·선택지 상자는 한 색 그대로 |
| K6 | `/save`: 저장 폴더, 마지막 저장 시각, 내보낸 파일 수와 가장 최근 파일, 쓰는 법. `/save export [파일\|폴더]`: 현재 판(`save.json`)과 프로필(`profile.json`: 기록·보너스·도감·설정)을 JSON 파일 하나로 쓴다. 기본 위치는 저장 폴더의 `export\lupin-yyyyMMdd-HHmmss.json`이다. 상대 경로는 `export` 폴더 기준이고, 다른 곳(USB 등)은 절대 경로를 적을 때만 쓴다. 현재 폴더에는 쓰지 않는다(업무 폴더에 게임 파일이 생기지 않게) |
| K7 | `/save import <파일>`: 파일을 읽어 확인한 뒤 상자(가져올 판·날짜·총자산·판 기록 수, 지금 판)를 띄우고 한 번 더 묻는다(기본 선택 No). 가져오기 전에 지금 데이터를 `export\before-import-yyyyMMdd-HHmmss.json`으로 자동 내보낸다(되돌릴 수 있게). 바꾼 뒤 내보낸 시각부터 지난 실제 시간을 꺼져 있던 시간으로 반영하고(상한 적용, 부재 중 요약), 보스키를 다시 등록한다. 상대 경로는 `export` 폴더 기준. 자동완성은 `export` 폴더의 파일 이름(최근 순) |
| K8 | 내보내기 파일 형식: `{ "Format": "lupin-farm-export", "Version": 1, "ExportedAt": UTC 시각, "Save": GameState, "Profile": Profile }`. 형식이 다르거나 버전이 더 높거나 판·프로필이 없으면 거부하고 지금 데이터는 그대로 둔다. 가져온 데이터는 `Normalize()`를 거친다 |
| K9 | 입력창에 `/place sprinkler <칸> [레벨]` 또는 `/upgrade sprinkler <칸>`이 칸까지 적혀 있고 그 칸·레벨로 놓거나 올릴 수 있으면, 농장 그림에 놓거나 올린 뒤의 물 범위를 노란 테두리로 미리 그린다(밤에도 어둡게 하지 않는다). 지금 범위(파란 테두리)는 그대로 둔다. 골드는 보지 않는다(모자라도 어디까지 닿는지 볼 수 있게). 칸이 화면에 보이는 구역이 아니거나 놓을 수 없는 칸(잠김, 작물, 이미 스프링클러, 보관함에 그 레벨 없음, 최대 레벨)이면 그리지 않는다 |
| K10 | 정보 칸의 창고·씨앗 아래 줄에 `보관함  스프링클러 n개`(아직 놓지 않은 스프링클러 수)를 보여 준다. 없으면 `-`. `다음` 줄은 한 줄 내려간다(창고·씨앗 값이 길어도 겹치지 않게 한 줄을 쓴다) |
| K11 | `/place sprinkler <칸> [레벨]`: 레벨을 적으면 보관함의 그 레벨을 놓는다(`2` 또는 `lv2`). 적지 않으면 지금처럼 가장 높은 레벨. 그 레벨이 보관함에 없으면 오류에 있는 레벨을 적는다. 자동완성: 칸 다음에 보관함에 있는 레벨(`3 · Lv3 ×1`) |
| K12 | 밸런스: `tests.exe balance`로 플레이어 세 유형(자주 = 게임 6시간마다, 보통 = 하루마다, 가끔 = 이틀마다 들여다봄)이 명령으로 농사·구매·자동화를 하는 시뮬레이션을 돌려 3장 목표와 비교하고, `Content.cs` 수치를 고친다. 바꾼 값은 `02` 3장과 개발 명세에 전·후를 남긴다. 보통 유형의 진행이 목표 범위에 들도록 `tests`에 검사를 둔다 |

## 3. 밸런스 목표 (K12)

기본 배속(실제 60초 = 게임 1시간)에서 게임 하루는 실제 24분, 근무일 8시간은 게임 20일이다. "보통" 유형(게임 하루마다 = 실제 24분마다 들여다봄) 기준이다.

| 단계 | 목표 (게임 날짜) | 실제 시간 (기본 배속) | 이유 |
| --- | --- | --- | --- |
| 농기구 첫 Lv2 | Day 3 이내 | 1시간 남짓 | Lv1은 칸마다 명령을 쳐야 한다 (M1 이슈 5) |
| 첫 스프링클러 | Day 15~30 (처음 Day 10 이내에서 조정, M5 이슈 4) | 0.75~1.5 근무일 | 시작 칸은 A줄 6칸이라 B줄이 열려야(12칸 이상) 스프링클러가 제값을 한다 |
| 첫 자동화 (컨트롤러 + 자동 수확기) | Day 20~35 | 1~1.5 근무일 | 자동화가 이 게임의 차별점이다 |
| 구역 2 | Day 30~50 | 1.5~2.5 근무일 | 큰 목표 하나가 며칠 안에 닿는다 |
| 총자산 100K (첫 프레스티지 가능) | Day 60~100 | 3~5 근무일 | 첫 주 안에 Lupin Bloom을 본다 |
| 총자산 1M | Day 180~260 (처음 Day 120~200에서 조정, M5 이슈 5) | 9~13 근무일 | 보너스 없는 첫 판 기준. 두 번째 판부터는 영구 보너스로 빨라진다 |

- 작물: 같은 계절 안에서 한 작물이 다른 작물보다 모든 면(하루당 이익, 해금 비용 대비)에서 앞서지 않게 한다. 비싼 해금 작물은 하루당 이익이 더 높아야 한다.
- 투자: 칸·농기구·장비의 투자 회수 기간(이익으로 값을 되찾는 게임 날짜)이 단계마다 크게 튀지 않게 한다.
