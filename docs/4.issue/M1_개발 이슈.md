# M1_개발 이슈

작성일: 2026-11-26 · M1 개발 중 정한 해석과 문제. 항목은 현상 → 원인 → 조치 → 반영 순서로 적는다.

## 1. `conhost.exe`로 띄워도 Windows Terminal 창이 열림

- 현상: 화면 확인용으로 `conhost.exe bin\lupin.exe`를 실행했는데 conhost 창이 아니라 Windows Terminal 창이 열렸고, 스크립트는 창을 찾지 못했다.
- 원인: Windows 11의 "기본 터미널"이 Windows Terminal이라 새 콘솔이 넘어간다.
- 조치: `wt.exe -w new --size 120,30`으로 새 창을 직접 열고, 새로 생긴 `CASCADIA_HOSTING_WINDOW_CLASS` 창을 찾아 `PrintWindow`로 그 창만 캡처했다. 실제 저장 폴더를 건드리지 않도록 `LUPIN_HOME`으로 임시 폴더를 썼다.
- 반영: `src/Program.cs` (`LUPIN_HOME`), 개발 명세 4장

## 2. 입력 주입 검증 도구가 보안 프로그램에 막힘 (사용자 확인으로 대체)

- 현상: 다른 창으로 키가 새지 않도록, 게임 콘솔 입력 버퍼에 직접 키·마우스 이벤트를 넣는 작은 도구(`AttachConsole` + `WriteConsoleInputW`)를 만들었다. 이 도구는 실행(액세스 거부)도, 복사·읽기도 막혔다.
- 원인(추정): 콘솔 입력 주입은 보안 프로그램이 의심하는 동작이다. 회사 PC의 보안 프로그램이 막은 것으로 보인다.
- 조치: 우회하지 않고 이 방식을 중단했다. 도구 파일은 지웠다. 키·마우스·보스키는 사용자가 직접 확인한다 (개발 명세 8장 U1~U4). 명령 처리 자체는 테스트(`CommandTests`)로 검증했다.
- 주의: 검증 중 테스트용 Windows Terminal 창이 세 번 열렸다. 제 테스트 창인 것을 캡처로 확인한 뒤 모두 닫았다.
- 반영: 개발 명세 1장, 8장

## 3. 게임을 강제 종료하면 터미널에 게임 화면이 남음

- 현상: 테스트 중 `Stop-Process`로 게임을 끄자, 그 탭에 게임 화면(대체 화면 버퍼)이 남고 "프로세스 종료됨" 문구가 떴다.
- 원인: 강제 종료는 정리 코드(대체 화면 나가기, 콘솔 모드 복구)를 건너뛴다.
- 조치: 정상 종료(`Ctrl+C` 두 번, `/exit`)와 예외는 모두 정리 순서를 거친다. 창을 닫거나 로그오프할 때는 `SetConsoleCtrlHandler`로 저장만 한다. 강제 종료는 대비할 수 없으므로 탭을 닫으면 된다.
- 반영: `src/Ui/App.cs` (`OnConsoleCtrl`), `src/Program.cs`

## 4. 공백 뒤에서 Enter를 누르면 실행 대신 자동완성이 채워짐

- 현상: 인자마다 후보 목록이 뜨기 때문에, `/plant turnip ` 뒤에서 Enter를 누르면 첫 후보(`all`)가 채워졌다.
- 원인: Enter가 "후보가 지금 단어와 다르면 채우기"로만 동작했다. 빈 단어도 다르다고 판단했다.
- 조치: 단어를 치는 중(커서 앞에 글자가 있을 때)에만 Enter로 채우고, 빈 자리에서는 실행한다. 후보 중 지금 단어와 똑같은 것이 있으면 실행한다(`/harvest a` → 줄 A).
- 반영: `src/Ui/App.cs` (`Enter`), 개발 명세 7장

## 5. 밸런스: 농기구 Lv2 200G

- 판단: Lv1은 한 칸씩 명령을 쳐야 해서, 첫 업그레이드가 늦으면 M1을 해 보기 어렵다. 기능 정의서 K3에 따라 Lv2를 200G로 낮췄다. 시작 100G로 순무 6칸을 한 번 수확하면(실제 약 48분, 물 주기 두 번) 220G가 되어 바로 닿는다 (`CommandTests.TestFarmLoop`).
- 조정할 곳: `src/Data/Content.cs`의 `ToolUpgradeCost`. M5(밸런스)에서 다시 본다.
- 반영: `../1.architecture/02_도메인 모델 및 데이터 포맷.md` 3.3절
